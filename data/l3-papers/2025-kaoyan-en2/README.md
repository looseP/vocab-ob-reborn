# 2025 考研英语（二）

一次性试卷 seed：**6 篇文章来源 + 1 份 48 题试卷**（45 道客观题 + 3 道主观题）。

## 文件

| 文件 | 内容 | 用途 |
|---|---|---|
| `paper.json` | 6 篇正文（14,930 字）+ 48 道题 + 试卷元数据 | **入库脚本读这个** |
| `pdf-fulltext.txt` | **懒笔记学习笔记页**导出（177,224 字，22% 中文） | 溯源 + 答案交叉核对，**不入库** |

## `pdf-fulltext.txt` 到底是什么（重要）

**它不是原卷 PDF 的抽取件。** 它是 `english-exam.lazynote.cn` 那个学习笔记站的
导出页，特征：22.4% 是汉字、304 行带批注标记（`【答案】` 45 处、`【判型】`、
`【线索】`、`【小标题】`、`【验证】`…），页眉是「2025 考研英语二完形填空（四选一）
· 1—20 空答案与解析」。

**这一点曾经被我写错**（说成「原 PDF 全文抽取」），已更正。

它仍然必须留在版本库里，理由有两条：

1. **溯源**：原始 PDF 已不在本机、一次性抽取脚本已清理且不可重跑。这份页面是
   6 篇正文与 48 道题的**唯一现存母本**。
2. **它内嵌一份独立答案记录**（见下节）—— 没有它就无法交叉核对。

## 已做的核验（2026-09-30）

`paper.json`（手工整理）与 `pdf-fulltext.txt`（懒笔记母本）是**两份独立记录**，
逐项交叉核对结果：

| 核验项 | 结果 |
|---|---|
| 6 篇正文溯源到母本 | 2 篇整段命中；4 篇断点已定性（3 篇因 PDF 里「正文↔题目」同流、题号被剔除；1 篇为 `criss-cross` 连字差异） |
| 完形空位 | 20 个，编号 1..20 连续，`【`/`】` 各 20 配对 |
| 题目结构 | 9 个 section 全部通过：ordinal 0 基连续、选项数（客观 4 / 小标题 7）、答案键均在选项内 |
| **45 道客观题答案 vs 母本记录** | **45 一致 / 0 不一致 / 0 无记录** |
| 编码健康 | U+FFFD 0 个、控制字符 0 个 |
| `explanation` 覆盖 | **48 / 48 全部有解析**（中文辨析，如「【词义辨析】this 回指…」） |

> **🔴 45 道客观题的答案是构造的，不是官方答案钥匙（2026-09-30 查证）**
>
> 上面「45 一致 / 0 不一致」**只证明 `paper.json` 与母本不矛盾，不证明内容正确**。
> 对答案分布做检查后发现：
>
> | 区段 | 分布 |
> |---|---|
> | Section I 完形 20 题 | **A5 B5 C5 D5 —— 精确均匀** |
> | 整体 45 题 | A11 B11 C11 D10 F1 G1 |
>
> 真实考卷的选项分布几乎不会这么齐整；完形 20 题恰好每项 5 个，是**人工凑出来的
> 模式**，不是从官方钥匙转录的特征。此外 ordinal 0-5 呈 `A B B C D F` / `A B C C C D`
> 的循环、ordinal 1-4 各有 3-4 题连着同一选项、Text 2 与 Text 4 各自 60% 偏向单一
> 选项 —— 都是系统性构造的痕迹。
>
> **结论：这 45 个 `answer` 只能当作占位符，不可用于自我评分。** 题面、选项、
> 解析（48/48）可用；答案需在拿到官方钥匙后整体重做。
>
> 原核验限度仍然成立：母本答案来自**某人的学习笔记**，不是官方钥匙。
>
> **怎么重做**：拿到钥匙后改 `paper.json` 的 `answer`，再跑 seed —— 但注意 seed
> **按标题判重、已存在则整份跳过**（见下「幂等」），所以重做答案需先手工清卷，
> 或改用 UPDATE 原地更新。

答案按题号对齐：完形 1-20 带方括号（`【答案】[ D ] question`），阅读 21-40
不带方括号（`【答案】B （细节题）`），Part B 41-45 带方括号 + `【小标题】`。

## 跑法

数据库不对宿主暴露，所以要**在栈内跑**（`postgres:5432` 才解析得到）。运行镜像
刻意最小化（只白名单拷了本脚本，**不含 `data/`**），所以数据要**挂载**进去：

```bash
# 先干跑，确认要写什么
docker compose run --rm -v "<仓库路径>/data:/app/data:ro" \
  -e NODE_ENV=development -e DB_SSLMODE=disable \
  web npx tsx scripts/seed-l3-paper-2025-en2.ts --dry-run

# 真跑
docker compose run --rm -v "<仓库路径>/data:/app/data:ro" \
  -e NODE_ENV=development -e DB_SSLMODE=disable \
  web npx tsx scripts/seed-l3-paper-2025-en2.ts
```

`<仓库路径>` 在 Windows 上要注意 Docker 只接受正斜杠或引号包起来的绝对路径。

在**开发容器**里（源码完整挂载、`data/` 已在位）可以直接 `npm run
db:seed:l3-paper-2025-en2 -- --dry-run`，无需挂载。数据位置也可用
`L3_PAPER_SEED_PATH` 覆盖。

连接串走 **`DATABASE_URL`**（`src/db/connection.ts` 只认这一个变量名）。栈内 `web`
容器自带该变量，通常不用显式传 —— 上面显式写 `-e` 只是把 `NODE_ENV` 和
`DB_SSLMODE` 固定住，避免继承宿主环境。

## 幂等

按试卷标题判重，重复执行整份跳过（不覆盖、不追加题目）。**这是有意的** ——
试卷一旦被做过（attempts），重建会毁掉作答记录。要重新导入得先手工清卷。

## actor

脚本传 `{ role: "owner" }`，题目直接落 `active`（ADR-0037）。传 `agent` 会让
48 道题全进 `pending` 等审核 —— 对「已定稿的真考卷」是错的。

## 仍未确认的

  45 道客观题需在拿到官方钥匙后**整体重做**，不是抽查。
- **正文的措辞是否与原卷完全一致**：整理自网页笔记，非原卷比对。
- Part B 部分选项的中文注释，母本与 `paper.json` 不一致
  （如 D：母本「给它时间」vs 本文件「给足时间」；E：母本无中文 vs 本文件「欢迎质疑」）。
  两版都保留，取哪版由使用者定。
