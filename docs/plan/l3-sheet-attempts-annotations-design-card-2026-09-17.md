## 0. 本卡解决什么

批次一交付后，卷面已能做题、建注记、圈词入笔记，但作答本身还没有家：答案写哪、历史怎么管、做题时随手写的判据（"划线句子关联题号 + 自己的理由"）算什么、agent 评卷读什么。同学在 09-17 会话中连问带裁，本卡把批次二的数据模型一次定死：

1. 题型空间与整卷是什么关系（投影，不是双写面）；
2. 作答历史的管理粒度（**一题一套**，不是一张试卷一套）；
3. 草稿的服务端容器（题纸，两个 venue 统一）；
4. 草稿注记的生命周期（它是"主张"，需要被检验）；
5. 题纸价值交付后的收场（定格三档 + 冻结导出）。

**设计哲学红线（同学原话收口）**：payload/answers 是引用与派生，不是冻结副本——同一事实只存一份。凡出现"两份存储、一侧可删"的形状，就是双真相 bug 的胚胎，必须在建模期拆掉。

## 1. D7 双层投影：题型空间与整卷共享同一原子

**定案**：数据层唯一写入面，题型空间与整卷都是投影，**不存在双向写入**。

```
数据层（唯一写入面）            投影层（纯组装，零数据所有权）
─────────────────────         ──────────────────────────────
l3_sources（原文）              题型空间 = 按 question_type 过滤的文件列表
l3_questions（挂 source）       整卷     = paper.payload 有序引用文件
l3_question_annotations         文件     = (source_id, question_type) ← 两边公共原子
l3_submissions（题纸，§3）
l3_question_attempts（§2）
```

- **文件是公共原子**：文件身份规则 `(source_id, question_type)`（V1 已定）。题型空间打开它、整卷把它串进 payload，用的是**同一个做题表面组件**（批次一文栏三通道 + 题卡 + 原文分析子区原样复用，按题型过滤 section）。
- **注记跨场景贯通免费**：注记挂题、锚点挂原文 content 偏移，与 venue 无关。题型空间写的注记，整卷做到同一题自动出现；反向同理。无同步、无双写。
- **整卷只拥有 chrome**：文件间导航、卷级进度、交卷入口。
- **作答痕迹可见、状态独立**（同学 09-17 拍板）：
  - 整卷题卡显示只读徽标「题型空间做过 N 次 · 最近 ✓/✗」，反向同理；作答状态两场景各自独立，净室模拟不被练习草稿污染；
  - 徽标点击 → **modal 预览**（默认，不打断做题流）：题干 + 该题历史 attempts 列表 + 注记摘要 +「去题型空间打开此文」链接；modal 与跳视图二选一做默认，设置项后续再说；
  - 历史支持**重复做**（两视角均可），历史记录不丢、按题可管理（§2）。

## 2. D8 作答历史题中心化：`l3_question_attempts`（修订 V3-T1）

**定案**：管理粒度从「卷/文件」下沉到「题」——一题一条历史链，管理/删除/重做全部按题操作。

### 2.1 双表分工

| 表 | 角色 | 内容 |
|---|---|---|
| `l3_question_attempts`（**新核心**） | 题级作答历史 | `question_id` + `venue('file'\|'paper')` + `sheet_id?`（→ 题纸）+ `answer` + **当场主观状态快照**（自评 + 旗标 + 标记，v2 扩，§4.6/§10）+ `created_at` + `status/deleted_at` |
| `l3_submissions`（题纸，§3） | 会话信封 | 题纸状态机与作用域，不再是历史管理单位 |

- **attempt 只存作答事实**（answer / venue / sheet_id / created_at / 当场自评快照）；**agent 评卷 verdict 真源仍归 `l3_grading_results`**——attempt 不写"判定"字段，否则 agent 改判时两处同步即腐化（拆掉的隐藏双真相点 #1）。
- 时空序：attempts 与 submissions **同批建（批次二）**，不留给批次三从 jsonb 派生——避免历史迁移。

### 2.2 软删 + 派生渲染（同学定稿，替换"交卷快照"方案）

1. attempt 删除 = **软删**（`status='deleted' + deleted_at`，照 ADR-0033 注记软删先例），不物理删；
2. 结果页逐题明细**直接从 attempts 按 sheet_id 派生渲染**——attempt 行本身不可变，这串行就是天然快照，submission 里不再冻第二份副本；卷级统计同源现算；
3. 删除的可见语义：**题历史列表不再出现该条；结果页该题显示"作答记录已清理"占位**（内容不展示、尊重删除意图），**统计保持交卷时口径**——软删行仍在库，统计天然不受影响，只有展示层两处分流（题历史过滤 deleted；结果页占位替换）；
4. **不做级联消失**（删一条历史改写已发生的成绩，更糟）。若用户真想"抹掉那次成绩"，正确操作对象是**整卷归档/隐藏**，与删单条 attempt 不共用一个按钮。

> 被否决方案：submissions.answers 与 attempts 双写同一事实——允许一侧删就必然漂移（"卷里显示 A、题历史里没有"是双真相的必然结果，不是快照方案的代价）。且 ADR-0030 已确立「payload 是引用不是冻结快照」，单独冻结作答副本是同一套设计里两套哲学。（双真相点 #2，建模期拆除）

## 3. D9 题纸：两个 venue 的统一作答容器（V3-T1 补条）

**问题**：file venue "无交卷概念、单题即答即存直接落 attempt" 与 "换新题纸 + 草稿 + 本次总结" 矛盾——草稿需要服务端容器。

**定案**：

- **题纸 = 一行 `l3_submissions`**，`file / paper` 只是作用域（scope 二选一，沿用 V3-T1 原约束形状）；产品名统一叫"**题纸**"；
- **状态机**：`draft`（任意涂画，防抖 PATCH 自动保存）→ `sealed`（定格：物化 attempts，此后 PATCH **409 拒写**）| `discarded`；
- file venue 的"即答即存" = 草稿自动保存，体感不变；"换新题纸" = 新开一行，多刷天然隔离（部分唯一索引一行 in_progress/draft 的既有约束沿用到作用域维度）；
- **定格是统一动作，两个 venue 都有**：paper 定格 = 交卷（评答案 + 评判据）；file 定格 = 结束刷题（**可只评判据**，即只把草稿注记提交给 agent 检验，答案可不进评卷）；
- 题纸是工作台、注记是产物——**价值交付后题纸可弃**（§5 定格三档）。

## 4. D10 草稿注记：主张的生命周期（本轮最重要修订）

**定性**：做题时"划线句子关联题号 + 写自己的判据"不是解题草稿，是**草稿注记**——注记的本质是"主张"，需要被检验。

### 4.1 不建第二张表：扩 `l3_question_annotations`（批次一容器复用）

| 新列 | 内容 |
|---|---|
| `stage` | `draft`（做题中产生，挂题纸）→ `submitted`（随题纸定格提交）→ `confirmed`（agent 检验通过 / owner 确认）；**存量回填 `confirmed`**；删除仍走既有 `status='deleted'` 软删列（与 stage 正交，批次二 ADR 钉死枚举归属） |
| `sheet_id` | 草稿期挂题纸（→ `l3_submissions.id`，可空；定格前必填） |
| `review` jsonb | agent 检验产物：`verdict sound\|questionable\|wrong` / `corrected_tags` / `comment` |

### 4.2 提交即授权（**显式修订 ADR-0033 §5**）

- 草稿注记**随题纸提交时作为评卷输入交给 agent**；**历史正式注记群默认不开放**；
- ADR-0033 §5「注记面 agent 连读都不开放」被本条**部分修订**：开放范围 = 该题纸 `stage=submitted` 的草稿注记，按题纸作用域收口。必须写进批次二 ADR，不能默认成立；授权注册表同步登记。

### 4.3 agent 写边界（不可篡改性）

- agent **只写 `review` 段**，永不写注记内容——`note` / 锚点 / 用户原判标签是不可篡改的原始事实；
- 订正放 `review.corrected_*`，**采纳归 owner**（owner 手动改自己的注记，或不理会）；
- 评卷产物加 `annotation_reviews[]` 段即可，**不新增白名单面**（不走 proposal 新类型）。

### 4.4 增量生长（注记资产的复利形状）

- **锚点幂等**（批次一已有：同题同锚点命中返回既有行）；
- **merge 不覆盖**：每张题纸只带它做到的部分，新题纸的草稿注记挂新 sheet，不改写历史注记；
- **覆盖度视图**「A✓ B✓ C— D—」：按题呈现选项被注记/检验覆盖的情况，**只呈现、不催**——不分析一眼错的选项是合法终态（对齐 baseline §1 积累型不催促）。

### 4.5 渲染规则

`stage=draft` 的注记仅在所属题纸的做题/解析模式可见（样式与正式注记区分，建议虚线描边），纯净模式与其他题纸上下文不显示；`submitted/confirmed` 沿用批次一"全程可见"规则。

### 4.6 标记（marks）：非资产化的题纸级痕迹（v2，2026-09-17 同学裁决）

- **定性**：做题中"划重点"（原文/题干/选项）是轻痕迹、不是主张，**不进注记表、不立 stage、不升格**——避免资产囤积负担；
- **存储**：题纸 `answers[questionId].marks: [{scope:'passage'|'stem'|'option', start, end, optionKey?}]`，防抖随题纸保存，**零迁移**（同 scope(+optionKey)+start+end 契约层去重）；
- **生命周期随题纸**：draft 期划词即存；定格分流——完整记录档物化进 `attempts.self_assessment`，增量/总结档随题纸弃；
- **资产化出口 = 导出**：标记经题纸导出（§6 v2）进入冻结档案——"导出即档案化"；agent 对标记正确性的分析发生在导出文档层面，系统内不建 verdict 流程；
- **渲染**：纯底色高亮，无角标无徽标无 cursor（划词铁律），不进覆盖度视图；sealed 结果页从 self_assessment.marks 还原；
- **v1 的 shape-driven 分轨设想（标记=锚点-only 注记、定格自动 confirmed）作废**：标记无主张可检验，升格 confirmed 是资产囤积；留在 draft 又会因 §4.5 可见性规则在定格后隐形。
- **验收补记（2026-09-17 同学拍板）**：scope 扩至选项文本（`option`+`optionKey` 定位）——选项行划词「标记重点」与「存疑」旗标（`optionFlags`）语义分立；选项行文本选择与点选作答的冲突由前端「选区非空即抑制点选」收口；揭示（解析模式）后选项行锁定、不接新标记。

### 4.7 stage 可变矩阵与撤回通道（v2）

| stage | note/锚点/标签 | 说明 |
|---|---|---|
| draft | 可编辑 | 现状不变 |
| submitted | **锁定（PATCH 409）** | 评审输入不可变；要改走撤回通道 |
| confirmed | **owner 可编辑** | 保批三"采纳归 owner"通道；`review` 段永远只读 |

- **撤回通道**：`POST /annotations/:id/withdraw`（submitted→draft），入参当前上下文 sheetId——注记重挂该题纸（无则幂等开纸），下次定格随新题纸重新升格；缺此通道会逼用户"删了重建"，破坏锚点幂等；
- 评卷时序一致性：owner 采纳改文后 review 成为历史快照（评的是"当时的主张"），是否复检由批三"再提交"决定，本批不做。

## 5. D11 定格三档：题纸的一次性收场

| 档位 | 作答事实 | 草稿注记 | 题纸 |
|---|---|---|---|
| **完整记录** | 物化 attempts | 全部升格（draft→submitted，待检验） | 保留 |
| **增量条目** | 不落 attempts | 全部升格 | 弃（discarded） |
| **只留总结** | 不落 | 只留"本次刷题总结"条 | 弃（discarded） |

- 定格动作时选择档位（默认完整记录）；
- "增量条目"服务场景：答得不值得存（全对无悬念 / 纯练手），但判据想留；
- "只留总结"服务场景：本次只有元认知值得留——总结条本身是一条无锚点注记（批次一 domain 已允许无锚点条目，note 必填），挂 file 作用域代表题；
- discarded 题纸行保留墓碑（状态 + 时间），内容字段清空可回收。

## 6. D12 导出 v2：随时可导的题纸全量快照（2026-09-17 扩写，取代 v1"仅定格后冻结档案"）

- **端点**：`GET /api/l3/sheets/:id/export`（owner-only）；`?withAnswers=1` 开关（draft 默认关防自我剧透，sealed 默认开）；
- **状态分流**：draft = 快照语义（数据源 `answers` 实时读，含 flags/marks 草稿，页眉标注"草稿快照 + 导出时刻"）；sealed = 冻结档案语义（attempts 派生）；discarded = 409（其产物是注记本身，不属题纸导出）；
- **单工件双读者**：Markdown 外壳（人读 / agent 直读）+ 尾部 ` ```json ` 全量结构化块（备份保真 / agent 解析）——一个文件同时服务"备份"与"绕过 MCP 直接喂 agent"；
- **内容清单**：页眉元信息（`exportSchemaVersion=2` + sha256 + 状态/时间线）→ 原文（marks `==高亮==` + 注记锚点编号）→ 题面+选项 → 作答与痕迹（choice/flags/marks/自评）→ 注记清单（stage 标注 + review）→ **评析段**（§11）→ 统计（仅 sealed）→ json 块；
- **只出不进、不回灌**红线不变：备份价值 = 归档 + 喂外部 agent，不是恢复入口（对齐 ADR-0025 原子写 + manifest 模式）；
- 版本演进：v1=1（批次二定格档案，已交付）；v2=2（本版）；页眉带版本与 CHANGELOG 注释；
- V3-T6"复制评卷指令"由导出弹层「复制全文」吸收，不再单列。

## 7. 批次二 ADR 必钉清单（同学指定，逐条）

1. attempt 软删 + 结果页派生渲染（本卡 §2.2）；
2. 题纸状态机（draft/sealed/discarded + 定格后 PATCH 409）（§3）；
3. 注记 stage 枚举 + 提交即授权（**Amends ADR-0033 §5**）（§4.1/§4.2）；
4. agent 不可写注记内容、评审并入评卷产物（不扩白名单面）（§4.3）；
5. attempt 只存作答事实，agent 评卷 verdict 真源仍归 `l3_grading_results`（§2.1，双真相点 #1）；
6. attempts 与 submissions 同批建（批次二），不留给批次三派生（§2.1）。

### v2 增补必钉（2026-09-17，随 T11 同批修订 ADR-0034）

7. stage 可变矩阵 + 撤回通道（§4.7）；
8. answers 显式键契约（choice/flags/optionFlags/marks）+ self_assessment 语义扩为当场主观状态快照（§4.6/§10）；
9. marks 非资产化：不进注记表、不升格，导出即档案化（§4.6）；
10. 评析区三层权限边界：注记 agent 只读（+review 段）/ 评析区 owner·agent 双写 / attempts 双方不可写——**Amends ADR-0029，agent 首个可写持久区**（§11）；
11. 评析区一题一条 upsert + last_editor 留痕、无历史版本（§11）；
12. 导出 v2 契约：状态分流 / 双读者结构 / withAnswers 默认值（§6）。

## 10. D13 旗标：存疑与待复查（v2，2026-09-17）

- **契约**：题纸 answers 立 zod strict 显式键形状 `{choice?, flags?: {doubt?, recheck?}, optionFlags?: string[], marks?}`——自由 jsonb 必须收口，防三个月腐化；

  - **待复查**（仅题级 `flags.recheck`）：流程状态，进定格软确认（"还有 N 题待复查"与未答题计数并列）；**随 `flags` 整段物化进 `self_assessment`**（2026-09-17 复核修订：原「不物化」改为保留——「当时想复查」的意图定格后仍可回看，批三评卷多一维对照信号；实现原即整段物化，本条为契约回写对齐）；

## 11. D14 评析区：一题一个的共建沉淀区（v2，2026-09-17 同学提出）

- **定位**：标记/旗标/草稿注记/作答是杂乱离散的原始痕迹，评析区是 **agent 解读后的结晶沉淀地**——痕迹轻资产化靠导出，沉淀重资产化靠评析区；
- **存储**：新表 `l3_question_assessments`（迁移 0035）：`(user_id, question_id)` UNIQUE、`question_id` FK→l3_questions ON DELETE CASCADE、`content_md`（≤20k）、`last_editor CHECK('owner','agent')`、时间戳；RLS own_all 单条 FOR ALL；vocab_app 四权双落点；
- **权限边界（Amends ADR-0029/0033，agent 首个可写持久区）**：三层分轨——注记 = 用户原始主张（agent 只读 + review 段）；**评析区 = owner/agent 共建**（同一 PUT 端点双身份，last_editor 留痕）；attempts = 不可变事实（双方都不可写）。注记不可篡改红线不变；
- **工作流闭环**：导出题纸 → 发外部 agent → 解读痕迹（标记对错/判据质量/旗标命中）→ 产出评析 → MCP agent 直写 PUT / 外部场景用户粘贴（同一端点）；
- **UI**：题卡「评析」子区（与「原文分析」并列，命名避让 L3QuestionAnalysis 组件）；**挂题不挂题纸**——跨题纸、跨 venue 永存；做题/解析模式均可编辑；
- **语义边界（同学 2026-09-17 确认）**：总结条管场次（随题纸时间线），评析区管题目（一题一条累计叙述）——双轨并存；
- **从简（同学确认）**：latest-wins 无历史版本，last_editor + updated_at 留痕兜底，版本历史待真实需求再加。
