## 一、结论先行

1. **可以**：入池范围扩为可选「含未学词」，这类计划**先曝光一遍（第 0 轮）再进入目标复习轮**；曝光轮**不计入**目标轮数，UI 标签显示「第 0 轮 · 首次曝光」，与「第 1 轮 · 复习」分开。
2. **缩时基准修正**：含未学词的计划，第 1 个复习轮才是基准轮（曝光轮不参与对比）；纯已学词计划维持现状（首个已收尾轮为基准）。**只比较已结算词集一致的轮**——按词数相同判定轮次等价是不可靠的（同数不同词），须按服务端实际结算词集比较。
3. **指标分三档，不发明数字**：
   - **已有**：曝光覆盖率（= 曝光轮的 `words_passed`，语义见 §四）、曝光耗时、首个复习轮耗时。
   - **需小改采集**（可靠、低成本）：每轮结算词集指纹、每轮通过率汇总（已实现为 `words_passed/words_total` 的语义修正）。
   - **本期明确不采**：首次回忆成功率（需要词级**首判**记录，与「刻意不建词级明细」的 §4.3 冲突，采集方式见 §五 的可选方案，默认不做）。
4. **旧计划不回改**：现存的先学后刷计划与轮次保留原语义与曲线口径；新增协议版本列区分新旧，迁移对存量行回填 legacy 值，不重建历史。

## 二、术语与协议版本

### 2.1 四个新术语（并入时注册进 `CONTEXT.md`，各带 `_Avoid_`）

- **曝光轮 (Exposure Round)**：`hulu_rounds.kind = 'exposure'` 的一轮，使命是**让每个词至少被看见一次**，不是逼回忆。交互 = 逐卡**直接展示**卡面（无遮答、无自认、无闸门），页结算语义 = 本页已曝光计数。
  _Avoid_: 把曝光轮算作一轮复习；对曝光卡要求「回忆后再翻」；用曝光轮的耗时当缩时基准。
- **复习轮 (Recall Round)**：`kind = 'recall'` 的一轮，即现行的遮答→回忆→翻开→自认→页闸门流程。
  _Avoid_: 把 legacy 轮直接改标 recall（见 §六 的兼容口径）。
- **可比较轮 (Comparable Rounds)**：两条已收尾的**复习轮**，其**已结算词集**完全一致（集合相等，非词数相等）。缩时降幅只在可比较轮之间计算。
  _Avoid_: 用 `words_total` 相等当等价判据（同数不同词会误判）；跨曝光轮/复习轮比耗时。
- **首次回忆成功率 (First-Recall Success Rate)**：每个词在**首个复习轮**的**首次**自认中「通过」的比例。这是词级首判事件，现表结构**采集不到**（§五）。
  _Avoid_: 用结算页的汇总数冒充（页可重自认后过闸，汇总里混着多次自认的最终结果）。

### 2.2 协议版本（migration 0051，见 §六）

| 列 | 表 | 取值 | 语义 |
| --- | --- | --- | --- |
| `protocol_version` | `hulu_plans` | `'v2'` 新计划 / `'legacy'` 存量回填 | 决定入池范围解释、轮次序列形状、曲线基准口径 |
| `kind` | `hulu_rounds` | `'exposure' | 'recall'` 新轮次 / `'legacy'` 存量回填 | 轮的语义标签；legacy 轮参与曲线但**永不作为基准轮**（见 §三） |
| `word_set_fingerprint` | `hulu_rounds` | text（见 §三） | 本轮**实际结算词集**的指纹，可比较轮的判据 |

## 三、轮次序列与缩时口径

### 3.1 入池与轮次序列

创建表单新增可选项「**包含还没复习过的词**」（默认**关**，保留 R9 先学后刷口径）：

- **关**（默认）：池 = `state ∈ ('learning','review','relearning')`（现行 R9 SQL 不变）；轮次序列 = 复习轮 × `target_rounds`（与现状一致）。
- **开**：池 = `state ∈ ('new','learning','review','relearning')`（同一 SQL 扩一个枚举值，稳定序 `created_at ASC, word_id ASC` 不变）；轮次序列 = **曝光轮 ×1 + 复习轮 × `target_rounds`**。
  - 曝光轮内**未曝光的词**（用户跳过未看）在进入复习轮时的处理：**仍留在复习轮词集中**——复习轮词集恒等于定格词集（只缩不换的定格语义不因曝光完成度而改）；UI 在复习轮页首提示「本页有 N 词在曝光轮未看过」。
  - 曝光轮**不计入** `target_rounds`：计划完成 = 第 `target_rounds` 个复习轮收尾（曝光轮已完成是开复习轮 1 的前置）。
  - 曝光轮可跳过：完成度 < 100% 时允许「直接开始第 1 轮复习」（显式按钮，一次确认），计划页持续显示曝光覆盖率缺口；**不允许**悄悄跳过。
- **池空判定**（两档）：默认档维持现行 422 文案；开「含未学词」后仍为空（即该词书四态都没有行）→ 422 文案：「该词书还没有词——先把词加进词书再冲刺。」
- **挂起开关**随入池词集走：开「含未学词」+ 开挂起时，`new` 词也在挂起范围内（快照回写机制不变——§六 与 R1 的自洽性天然成立，因为快照本来就支持 `new`）。完备设计 §六「挂起范围含 new」的旧描述与此重新一致。

### 3.2 缩时曲线修正（`HuluSpeedCurve`）

1. **分组**：只画 `kind ∈ ('recall','legacy')` 的已收尾轮；曝光轮不进图（其耗时在计划页单独展示「首次曝光耗时 X」一行，标签注明「曝光不计入缩时对比」）。
2. **基准轮**：图中**第一条**复习轮为基准（`drop = 0`，标签「基准轮」）。legacy 轮序列里，legacy 轮**永不**作为基准：若序列含 legacy 轮，基准 = 第一条 `kind = 'recall'` 的轮；若全是 legacy 轮，维持现行「首个已收尾轮为基准」（老计划口径不回改）。
3. **可比性判据（本轮的核心修正）**：`word_set_fingerprint` 一致的轮之间才算降幅；指纹不一致的轮照样画柱、但降幅位置显示「词集已变化，不与基准比较」。
   - 指纹 = 服务端在**轮收尾**时计算：本轮所有**已结算词 id 集合**（见 §四「结算词集」的推导）排序后的 SHA-256（hex 前 16 位即可，碰撞域足够）。**词数相同不算**——「两轮 24 词」可能是 24 个不同的词。
   - 现行实现**没有词级结算记录**，推导结算词集有两条路（实现时二选一，设计已拍板走 a）：
     a. **页级已结算词集**：轮收尾时，按 `pages_passed` 游标取前 N 个页的定格切片，过滤当前已删词 → 作为「已结算词集」的近似。近似边界：页内被删词在结算时点仍存活与否不可考（页级无明细），但删词后该页 `total` 漂移已被 D1 机制拦住重取，故误差可接受，且**口径声明写入免责声明**。
     b. ~~词级明细表~~：否决——违反 §4.3「刻意不建页级明细表/词级通过记录」的既定裁决，为一条曲线改红线不值。
4. **免责声明追加一条**（现有两条不动）：
   > 只有「已结算词集一致」的轮次才比较耗时；词书增删导致的词集漂移会让对应轮不参与降幅计算。

### 3.3 三个数量的诚实读法（回应「两轮同词数是否可比」）

- `words_total`（定格词数）：恒等于 `cardinality(word_ids)`，**不随删词变化**——它是「计划签了多少词」，不是「这轮过了多少词」。
- `words_passed`（累计自认通过数）：页闸门 80% 的下界决定了它**至少** ≈ 0.8 × 存活词数，但页被拦后重自认的通过数**不入库**（失败页不留记录，§4.3），所以它是「过闸页的自认通过总数」，不是「每个词的掌握结果」。
- 结论：两轮 `words_total` 相同，**只能说明定格集没变**（它本来就不变），连「两轮过了同一批词」都不能保证——必须靠结算词集指纹。

## 四、指标清单（分档，标注可得性）

| 指标 | 定义 | 数据源 | 可得性 | 展示位置 |
| --- | --- | --- | --- | --- |
| 曝光覆盖率 | 曝光轮 `words_passed / words_total`（曝光轮中该列语义 = 已曝光词数，见下） | `hulu_rounds` 行 | **已有**（复用列，语义随 `kind` 解释） | 计划页徽章「曝光 18/24」 |
| 首次曝光耗时 | 曝光轮 `elapsed_seconds`（墙钟，R5 同口径） | 同上 | **已有** | 计划页单行，不入曲线 |
| 首个复习轮耗时 | 第一条 `kind='recall'` 已收尾轮的 `elapsed_seconds` | 同上 | **已有** | 曲线基准柱 |
| 每轮通过率 | `words_passed / words_total`，**口径修正**为「过闸页自认通过数 ÷ 定格词数」 | 同上 | **已有**（修正的是**文案与命名**，不是数字） | 计划页每轮一行 |
| 缩时降幅 | 相对基准轮、且仅可比较轮 | 指纹 + elapsed | **需采集** `word_set_fingerprint`（§六） | 曲线（现行位置） |
| 首次回忆成功率 | 每词在首个复习轮的**首次**自认 = pass 的比例 | 词级首判事件 | **本期不采**（需词级记录，见 §五） | 不展示；FAQ 说明「为什么看不到」 |

**曝光轮的页结算语义**（复用现有管道，零新端点）：曝光轮中 `passed` 语义 = 本页已曝光词数（= 本页存活词数，因为曝光无自认），`total` = 本页存活词数——恒过闸（100% ≥ gate）。闸门函数不改；曝光轮前端**不发**与闸门相关的 UI（无「通过率」徽标，显示「已曝光 n/n」）。

## 五、首次回忆成功率：为什么本期不采（以及将来怎么采）

- **冲突点**：§4.3 明确「词级通过记录刻意不建」；首次回忆成功率是词级**首判**事件——用户在页内可以改自认（过 → 不过 → 过），结算时入库的只有最终汇总，首判序列**不可重建**。
- **本期处置**：不采、不展示、不留半成品字段。计划页 FAQ 一行说明：「首次回忆成功率需要逐词记录每次自认，与葫芦『只记页级汇总』的轻量设计冲突，本期不做。」
- **将来若要采**（另行立项的最小方案）：页结算请求体加**可选** `firstVerdicts: Record<wordId, "pass"|"miss">`（前端在本地捕获每词**第一次**自认，仅随过闸结算提交一次，落 `hulu_rounds` 的 `first_recall jsonb` 列）。这是可选新增、非 breaking；但它仍是词级数据，立项时须重开 §4.3 的裁决，不能顺手加。

## 六、迁移与兼容（migration 0051；0051 起手写 + DDL 幂等，ADR-0042 D4）

```sql
-- 全部幂等（IF NOT EXISTS / 守卫式回填），照 ADR-0042 §4 的 lint 口径。
ALTER TABLE hulu_plans
  ADD COLUMN IF NOT EXISTS protocol_version text NOT NULL DEFAULT 'legacy';
ALTER TABLE hulu_plans DROP CONSTRAINT IF EXISTS hulu_plans_protocol_check;
ALTER TABLE hulu_plans ADD CONSTRAINT hulu_plans_protocol_check
  CHECK (protocol_version IN ('v2','legacy'));

ALTER TABLE hulu_rounds
  ADD COLUMN IF NOT EXISTS kind text NOT NULL DEFAULT 'legacy';
ALTER TABLE hulu_rounds DROP CONSTRAINT IF EXISTS hulu_rounds_kind_check;
ALTER TABLE hulu_rounds ADD CONSTRAINT hulu_rounds_kind_check
  CHECK (kind IN ('exposure','recall','legacy'));

ALTER TABLE hulu_rounds
  ADD COLUMN IF NOT EXISTS word_set_fingerprint text;

-- 存量行即默认值（legacy / NULL fingerprint）：老计划与老轮次保持 R9–R11 口径，
-- 不回填指纹（重建不出可信的历史结算词集），老曲线维持现行画法。
-- 新代码写新行时显式给 'v2' / 'exposure'|'recall'，不吃默认值。
```

- **默认值放 legacy 而非 v2 的理由**：DEFAULT 是给「未感知新列的旧写入路径」的兜底；让它指向旧语义，滚动升级/回滚窗口内旧代码写出的行仍被正确解释（fail-safe）。
- **唯一索引不变**：`UNIQUE (plan_id, round_no)` 沿用——曝光轮就是 `round_no = 0`（CHECK 现无下界约束，无需改；v2 计划的第一条复习轮 `round_no = 1`）。「全计划至多一个未收尾轮」的服务层保证不变。
- **响应契约**：`huluRoundRowResponseSchema` 加 `kind` / `word_set_fingerprint`（response 新增字段对 breaking 门禁安全）；`huluPlanRowResponseSchema` 加 `protocol_version`。请求契约 `huluPlanCreateSchema` 加 `includeNewWords?: boolean = false`（可选新增 = 非 breaking，ADR-0036 §3 先例）。
- **曝光轮轮号**：UI 标签「第 0 轮 · 首次曝光」；`startRound` 在 v2 计划上若尚无曝光轮 → 开 `round_no = 0, kind = 'exposure'`；曝光轮收尾后才允许 `round_no = 1`（`finishRound` 对曝光轮不推进计划状态，仅写耗时与指纹）。
