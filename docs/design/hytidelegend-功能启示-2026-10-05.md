## 三、三条最值得抄的（深挖）

### 3.1 词汇语义关系图 —— 你差的就是把已有数据画出来

**它做到什么程度**：
- 关系不是"有 or 无"，而是**三态**：`relationships[]`（已确认，实线）/ `pendingRelations[]`（无法判断的表外候选，虚线 + 灰色占位节点）/ 拼写相似（`linkStatus: lemma_only`，目标词未建时保留词面，两端齐备后自动补齐双向链接）
- 词族**不画边**，用同族团簇 + 引力聚拢 + 间距约束表现（附 inherently：同族不画边是一个克制的设计决定，避免边爆炸）
- 布局有明确的配置旋钮（`familyNodeGap` 默认 8，0 恢复相切），节点随选中缩放，≥100% 才显示释义
- 500 节点上限 + 搜索/聚焦触达其余

**为什么对你价值最大**：这条几乎**零算法成本**。拼写字面相似度对方用 `2×LCS/(len(a)+len(b)) ≥ 0.75` 就搞定了（且明确排除别名、屈折词形、已确认同族），词族和语义关系你早就有了。**画布组件你也有**——`L3GraphCanvas` 已经是通用 `nodes/edges` 模型，直接复用即可。

**而且有个值得玩味的巧合**：对方这个项目里，这个英文/ubuntu  learning 功能就叫「**词汇星图**」。你的项目叫 **Vocab Observatory**。你要抄的功能，名字恰好是你自己的项目隐喻。

**落地形态建议**：不要另起 Tab，做成 `L3GraphCanvas` 的第二种 read model（`LexicalGraphReadModel`），节点 = 词，边 = synonym / antonym / derivation / word-family / spelling-similar。边的 status 三态直接对应你已有的关系可靠性（已核准 vs 候选）——**这恰好接得上工程篇讲的 verificationStatus**。两篇在这里汇合了。

### 3.2 助记意象图 + "这个不适合用联想法"的诚实出口

两件事要一起看。

**第一件：给 L1 的 Prototype / Mnemonic 配一张图。**
它的产出链路是：提取关键词 → 调整顺序 → 编口诀 → 自检覆盖 → 生成 `image_prompt`（一个完整、可直接交给生图工具的提示词）→ 用户确认 → 出图 → 归档。

配套有一份写得相当扎实的共享规范（`utils/references/mnemonic-association-principles.md`），九条场景增强原则：色彩 / 想象 / 节奏 / **动感** / **至少两种感官线索** / 性联想（默认允许）/ 顺序条理 / 编码 / 立体感。其中「动感」（让关键物象发生动作，动态画面比静态更容易记住）和「至少两种感官线索」这两条是有记忆学依据的，不是随便列的。

你的 L1 卡片现在是 Tier 0 答案层 + Tier 1 锚点层（ Prototype/Mnemonic 做成低可见 pills，单行截断）+ Tier 2 网络层。**Prototype 和 Mnemonic 恰好就是"意象—助记"这一对**——它们天生是图，却只以文字 pills 呈现，而且被单行截断了。这是个明显的浪费。

**第二件（更重要）：`self_check` 三档 —— good / weak / bad。**

它的规定是：当联想牵强、增加新负担、无法想象、只是解释知识而不能帮助回忆原句，**或不如直接背诵时**，Agent 必须选 `weak` 或 `bad`，并且要在结果里显眼地告诉用户「这个例子不适合直接使用联想法」和替代建议。找不到合格句子时，**只展示关键词，不展示口诀和生图提示词**。

这是一个我非常想让你拿走的设计：**给 AI 生成内容一个「我生成了，但我不建议你用」的合法出口。**

对照你的现状：L1 三件套（Prototype / Mnemonic / Semantic Chain）+ Etymology Narrative 是 AI 生成的，走候选池 → 采纳。整个链路只有「生成成功 / 失败」两态，**没有"生成了但这是牵强的"**。而助记这个品类的真相是：**相当一部分词的助记本来就编不好**，硬编一个谐音口诀的害处大于不编——它会占用一个记忆槽位，还可能是错的。

工程篇里我建议加 `verificationStatus`；这里是它的功能侧呼应——`self_check` 其实就是生成方自己交出的第一份 verification 意见。**如果 Generated which content 自带"我这��不靠谱"的标记，采纳页就能据此给建议，而不必等用户自己去判断。**

### 3.3 第五个选项：「没听过 / 不清楚 / 没把握」

这是整份分析里**改动最小、单项收益最高**的一条。

它的诊断题规定：四个实质选项之后**必须**追加第五项「没听过 / 不清楚 / 没把握」，且第五项不能是正确答案。考的直接是定义、辨析、应用或推理，**禁止出「你是否听过某名词」**这类题。

理由很硬：一道四选一题，纯猜测的正确率是 25%。而你现在的 **L2 Drill Step 0 辨析正是四选一 MCQ，正确答案 đó→good、答错→again**。猜对一次就等于拿到了"掌握了这个词"的证据，直接进入 Step 1 生产句，还写进了 `-` FSRS 的 good 评分。

**不确定本身就是一种信息，而且是最有价值的那一种。** 加了第五选项之后：
- 「不知道」和「知道但选错」被区分开——前者是没学过，后者是学错了，两种补救策略完全不同
- 猜测不再污染 FSRS 的 good 率
- 多选诊断机制Future Emergent future doctor：同一 vidékiuvej versus 有了"我确定不会"这个诚实选项

落地成本：一个选项 + 三种 outcome 映射（选第五 → again，且不标记为"辨析出错"）。

## 四、四条次优先

**4.1 错题库从「派生清单」升级为「归纳层」**
它的错题本不是错题列表，而是：每个评分不足的知识点**必须有对应的一条归纳**，归纳里含薄弱点、普遍规律、纠正建议，脚本去重归并，每条归纳下的例题从 1 编号并注明出处，选择题例子要包含全部选项。
你的错题库（ADR-0021 派生）目前只回答"哪些错了"。差的是"**为什么反复错、共同规律是什么**"。你的 subset'avoit loi 已经有** subdirectory structure** 派 label（同义替换/偷换概念/无中生有/过度推断/正反颠倒/张冠李戴/答非所问）——**这套标签就是现成的归纳维度**，按标签×知识点做归并即可，不用重新发明分类法。

**4.2 报告要显式承认盲区**
它的学习报告固定栏目里有一项叫「**未验证能力**」，并且明确限制结论范围：*选择题不能证明自主解释和迁移能力*。
你的 dashboard 有 reviewedToday/7d/30d、rating distribution、heatmap、weakSignal——全是**已发生的事**。缺一个「**没测过的**」视角： `盖 domicile` after states: rate limiting → 用户会以为"没出现=没问题"。

**4.3 批改必读闸门**
它的规定极严：批改完成后**必须先在对话中原样展示完整 `feedback_markdown`（逐题题干、作答原话、评分、意见、完整参考答案、差异、本课总结），留痕后才能继续下一课**；`paused` 时退回对应的 `feedback_delivery_required`，注释里写得很直白——"*禁止把文件生成成功当作已展示*"。
你的 CONTEXT.md 说错题本题库是个 **hub**："an error-book row that cannot be re-practised (that is a dead end, not a hub)"。但 hub 只保证"能回去练"，没保证"回去之前先看懂分析"。中间差一道消费闸。

**4.4 轻量难度信号**
它每课末尾放两个不计分项：难度 A 太简单 / B 适中 / C 太难（**空白默认 B**）+ 可选疑问。重磅雕 surefire the hardstream left uncertainties：这块信号直接驱动下一课的调整（`adaptation_applied{feedback_id, changes}`，绑定调整依据）。
你的 damín self-assessment 只存在于 L2 Drill 生产步（passed/weak）和 question attempt 里，且都偏"结果"而非"体感"。一个不计入 FSRS、不影响 due 的纯体感信号成本极低，但它是"AI 知道该讲多难"的唯一输入。

## 五、三条远期 / 视场景而定

- **学习内容播客化**：注意方向和你想的相反——你的 L3 有声文章是**用户导入的素材**；它做的是**把已产出的学习内容**（课程讲义）转成双人问答 MP3。对你来说这意味着把 L2 词条内容做成"磨耳朵"曲目，是一个**消费侧**能力，不是捕获侧。考研场景里通勤/睡前听的需求是真存在的，但优先级低于前四�_section。
- **手写答题卡照片**：属于 writing workspace 的延伸，功能是"我在真实答题卡上写出来是什么效果"——对**卷面分**有实际意义（字���大小、行距、涂改观感）。用户是考研的，这条的场景贴合度高于它的平均水平。
- **可插拔评分工具**（`create-tool`）：用户提供评分标准/范文资料 → 抽出 rubric + 可复用语言项目 → 之后按此工具批改。**它的关键约束值得抄**："仓库不自带具体作文工具；没有可用工具时必须暂停提示先创建；本次不会凭空编造评分标准。" —— 这和你的 proposal-only 是同一个哲学在写作场景的表达：**不编造权威**。

## 六、不要抄的三条

1. **用艾宾浩斯替换 FSRS** —— 反方向。它的 [1,2,4,7,15] 自己也写明"是本项目的排程约定，不声称是实验唯一规定的时间表"。你的 FSRS 更强。
2. **把葫芦法的 ≥80% 门槛直接套进复习** —— 它自己规定葫芦计划**不写 FSRS**（宝山区 neurology）。两者服务的是不同心智模型：葫芦管"这批我整体过了没"，FSRS 管"这张卡什么时候到期"。可以并存，不能合并。
3. **照搬「双图 learning route」到词汇层** —— 单词不是有前置依赖的知识体系，`我们俩 agreed backwards` 硬造 L1 的依赖图会把"没有结构"伪装成"有结构"。它的依赖图有价值，是因为它的输入是**有章节结构的教材**；你的输入是词表和采集到的例句。这条只对 sub-space 的知识点/方法论成立。

## 七、一句话总结

工程篇的结论是"**让提案自带不可伪造的出处指纹**"；功能篇的结论是另一句：

> **它把「记忆」当成多模态、带自我否定能力的产物来经营 —— 而 vocab-ob 目前把学习内容当成文本 row。**

意象图对应多模态，`self_check` 对应自我否定，第五选项对应"诚实地表达不知道"。这三样东西有一个共同点：**它们都在给学习系统补充「负信息」**——图片提供冗余线索，weak 标记说"别信我"，第五选项说"我不会"。

而一个只有正信息的记忆系统，FSRS 会把它的每一次误判都安静地放大成长期记忆。
