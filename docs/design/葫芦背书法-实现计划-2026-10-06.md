## 〇、本计划相对上一版设计的三处修正

上一版设计有三处经源码核对后不成立，这里先改口，后文全部按修正后的口径写。

### 修正 1：落点不是 `sessions.mode='hulu'`，是独立表

上一版倾向复用 `sessions`。核对后否决，四条硬理由：

1. **粒度错位。** `sessions`（`src/db/schema.ts:313`）是「一次坐次」：`started_at` / `ended_at` / `cards_seen`，
   语义是一次打开到一次关闭。葫芦计划跨**数周、数轮**，一轮都不一定在一次坐次里走完。
2. **唯一约束会卡死。** `idx_sessions_one_active` 是 `(user_id, wordbook_id, mode) WHERE ended_at IS NULL` 的部分唯一索引。
   复用它意味着一个词书同时只能有一个活跃葫芦计划——这恰好是想要的，但**代价是把"计划"和"坐次"焊死成同一行**，
   中途退出再进入只能靠复活同一行，会话恢复语义全乱。
3. **枚举并不反映模式。** `sessions_mode_check`（`:344`）只认 `review / cram / preview / l2_drill`。
   `ladder` 和 `zen` 都**不在**里面：`zen` 在请求层被映射回 `review`
   （`ReviewPage.tsx` 的 `apiMode = isFreeSelection ? "preview" : reviewMode === "zen" ? "review" : reviewMode`）。
   所以"模式清单"和"sessions.mode 枚举"本来就是两套东西，加 `hulu` 进枚举是在混淆它们。
4. **项目已有正确先例。** `l3_sessions`（`:1193`）的文件头注释明确写着
   「不用 sessions 表（L3 会话走 l3_sessions）」，形状是 `plan jsonb`（只存引用 + version）+
   `status ∈ {active, completed, abandoned}` + **零 FSRS 列**。葫芦照这个形状建自己的表。

### 修正 2：「缩时曲线全局化」不能按原话说

上一版把缩时曲线放到所有模式。核对后收缩：

- `review` 没有「轮」。一次复习会话混着不同到期日的词，"这周第三轮比第一轮快了多少"在数据上**不存在**。
  硬凑就是再造一个 `due7d = dueToday * 1.5`（`stats.service.ts:63-68`，注释自己承认没读 `due_at`）那样的假指标。
- 因此**缩时曲线只消费葫芦自己的轮次记录**，不对外输出、不被其他模式读取。
- 日常复习确实缺一个「我在变强」的可观测信号（这是葫芦真正值钱的洞察），但它必须是**另一个指标、另一张图**，
  用 `review_logs` 里真实存在的量来算。见 §5.4，单独立项，不塞进本期。

### 修正 3：80% 不是「自评勾选」，是「检索后自认」

演示里用勾选框是为了把闸门语义跑通。真做时若保留"看一眼就打勾"，检索练习（Roediger & Karpicke 2006）
这条葫芦仅剩的硬证据就空了。正确交互是：**先遮答案 → 用户尝试回忆 → 翻开 → 再自认过/不过**。
闸门统计的是"翻开后自认通过"的比例，不是"看过"的比例。

## 一、一句话定位

> 葫芦是挂在 **L1 词书**上的**阶段性冲刺计划**：整批词按页推进、页级 80% 检索闸门、
> 多轮滚动、只记轮次耗时、**零 FSRS 写入**。
> 它不替换 `review` / `cram` / `preview` / `zen` / `ladder` 任何一个，
> 也不碰 `l3_sessions` 及其四类会话。它是第 6 个**显式**复习模式，加一张自己的计划表。

## 二、与原学习架构的关系总账

先把 vocab-ob 现有的三层调度摊开，葫芦只加在最左列的最底一行。

| 层 | 容器 | 调度 | 写入 | 葫芦的关系 |
| --- | --- | --- | --- | --- |
| L1 词 | `sessions`（一次坐次） | FSRS 逐词 | `review_logs` + `user_word_progress` | **并行，零写入交集** |
| L2 短语/用法 | `l2_drill` | 独立 FSRS 轨（ADR-0002） | L2 review outbox | **完全不涉及** |
| L3 语境/句子 | `l3_sessions`（计划 + 引用） | 无（ADR-0004 §6 红线） | `l3_practice_attempts` | **形态借鉴，数据隔离** |

### 2.1 融入点（6 个，全部是"照抄既有形状"）

| # | 融入什么 | 照哪条先例 |
| --- | --- | --- |
| F1 | 计划只存 **引用 + 版本号**，不存词面、释义、渲染结果 | `l3_sessions.plan`（ADR-0019 §2）：「不存 HTML 产物，每次打开现拉现渲染」 |

### 2.2 冲突点（8 个，每条给处理决议）

| # | 冲突 | 为什么真是冲突 | 决议 |
| --- | --- | --- | --- |
| C1 | **「L1 速刷不进会话」**（CONTEXT.md / ADR-0019 §2：<5s/词 的节奏不容会话开销） | 葫芦要记轮次耗时，看起来必须有会话容器 | **计划与坐次分离**。计划表只在三个时点被碰：创建、每页结算、每轮收尾。逐词翻卡是纯前端状态，零请求。见 §4.3 |
| C2 | `sessions` 表的坐次语义与枚举 | 见修正 1 | **不碰 `sessions` 表、不加枚举值、不改 `idx_sessions_one_active`** |
| C3 | `cram` 的「错题回尾直到会」比 80% 更严 | 把 80% 塞进 cram 是把"精练"降级成"粗刷" | **80% 闸门只存在于葫芦**。`DrillSession` 一行不改 |
| C4 | `preview`「不评分、不写入数据」 | 缩时必须写耗时 | **`preview` 保持零写入**。葫芦不借它的任何代码路径 |
| C5 | ADR-0004 §6 / ADR-0005「L3 不参与 FSRS」与 ADR-0002 双轨隔离 | 若把葫芦塞进 `l3_sessions`，等于让一个 L1 词书功能写进 L3 的类型枚举 | **葫芦不进 `l3_sessions_type_check`**。`cram_pack` 继续只服务 L3 素材攻坚 |
| C6 | **同一批词被两套系统同时追** | 冲刺期内这些词仍按 FSRS 到期出现在 `review` 队列里，用户等于把同一批词背两遍，负担直接叠加 | **不自动暂停**（静默改队列 = ladder 开关踩过的坑）。提供**显式、可逆、按词书**的「冲刺期让这批词退出到期队列」，实现为复用 `suspended` 状态（ADR-0020），退出或放弃计划时自动恢复。默认关闭 |
| C7 | **假指标先例** | `computeForecast` 用 `dueToday * 1.5` 冒充预测，注释承认没读 `due_at` | 葫芦的每个数字都必须可回溯到 `hulu_rounds` 里的一行。**禁止**用词数或通过率反推耗时（演示里的反推只是演示） |
| C8 | **对象错配** | 葫芦原场景是 8 本大部头专业课书、考完即弃；vocab-ob 是长期词库 | 葫芦在此只用于**有明确截止日期的大批量词表**（考研/雅思词书、考前 N 天）。UI 文案不得把它描述成"更好的复习方式"，必须写成"考前冲刺"。无截止日期就不该建计划 |

## 三、明确不做什么

这些都是真有诱惑力、也真会破坏架构的选项，写下来防止实现时回潮。

1. **不把葫芦做成 `review` 的过滤器或设置项开关。** ADR-0036 §4 的修订就是专门堵这条路的。
2. **不写 `user_word_progress`、不写 `review_logs`、不调用 `submitAnswer`。** 包括"顺便记一下"。
3. **不把未通过的词注入 `cram` 错题队列，也不进 L3 错题库。** 错题库是 `attempts(outcome='wrong')` 的派生视图（ADR-0019 §1），葫芦的"未通过"是页级比例事件，不是词级错题。
4. **不让一轮的通过/失败改变下一轮的词序或词集。** 词集在创建时定格，各轮重复同一批。这是葫芦"靠遍数补质量"的定义本身。
5. **不新增 npm 依赖**（ADR-0004 依赖克制；ADR-0036 §5 已重申）。
6. **不做服务端计时。** 耗时由客户端在轮次开始/结束时上报时间戳，服务端只存不推。
7. **不在本期做"日常复习的变强信号"**（§5.4），避免两个指标共用一张图。

## 四、数据模型

### 4.1 两张新表

**`hulu_plans`** — 一个词书至多一个活跃计划

| 列 | 类型 | 约束 / 说明 |
| --- | --- | --- |
| `id` | uuid pk | |
| `user_id` | uuid | FK → profiles，RLS `auth.uid() = user_id` |
| `wordbook_id` | uuid | 复合 FK `(wordbook_id, user_id)` → `wordbooks(id, user_id)`，级联删除 |
| `direction` | text | 复用方向枚举 `通用/考研/雅思`，可空 |
| `exam_date` | date | **必填**（C8：没有截止日期就不是葫芦的适用场景） |
| `target_rounds` | smallint | `CHECK BETWEEN 2 AND 8`，默认 4 |
| `page_size` | smallint | `CHECK BETWEEN 5 AND 50`，默认 20 |
| `gate_ratio` | numeric(3,2) | `CHECK BETWEEN 0.50 AND 1.00`，默认 0.80。**存下来而不是写死**，避免以后调参要迁移 |
| `word_ids` | uuid[] | **创建时定格**的词序。只存 id，不存词面（F1） |
| `status` | text | `active / completed / abandoned`，默认 `active` |
| `suspend_review` | boolean | 默认 `false`。C6 的显式开关 |
| `started_at` / `ended_at` / `created_at` | timestamptz | |

索引与约束：

- 部分唯一索引 `idx_hulu_plans_one_active ON (user_id, wordbook_id) WHERE status = 'active'`。
  这是从 `idx_sessions_one_active` 学来的形状，但谓词用 `status` 而不是 `ended_at`，因为计划的"结束"是业务状态不是坐次状态。
- `CHECK (cardinality(word_ids) BETWEEN 1 AND 20000)`。

**`hulu_rounds`** — 轮次是耗时的唯一真源

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | uuid pk | |
| `plan_id` | uuid | FK → hulu_plans，级联删除 |
| `user_id` | uuid | 冗余，用于 RLS，复合 FK 回计划保证不挂到别人的计划 |
| `round_no` | smallint | `UNIQUE (plan_id, round_no)` |
| `started_at` | timestamptz | 客户端上报 |
| `ended_at` | timestamptz | 可空 = 进行中 |
| `elapsed_seconds` | integer | 结束时写入，**只增不改** |
| `pages_passed` | smallint | 过闸门的页数 |
| `words_passed` | integer | 自认通过的词次数（跨页累加，同一词一轮只计一次） |
| `words_total` | integer | = `cardinality(word_ids)`，冗余以便计划被删后曲线仍可解释 |

刻意**不建**的表：页级明细、词级通过记录。闸门是页级事件，过了就过了，没有复盘价值；
留词级记录会诱使下一步把它接进错题库（破坏第 3 条"不做什么"）。

### 4.2 词集定格规则

- 创建时按词书（+ 可选 direction）取词，排成稳定顺序，写入 `word_ids`。
- 之后词书里新增/删除的词**不影响**进行中的计划。这直接沿用 P0-1 题单定格的决策理由
  （`practice-loop-p0p1` §P0-1：「开卷后加题会在交卷时静默变卷」）。
- 定格里的词若被删除：渲染时剔除，**不替换成别的词**（同样沿用「只缩不换」）。
- 词面、音标、释义、助记全部走现有词条读取，计划里不存任何文本（F1）。

### 4.3 写入时点（这是 C1 的解法）

| 时点 | 请求 | 频率 |
| --- | --- | --- |
| 创建计划 | 1 次 | 一次 |
| 轮次开始 | 1 次 | 每轮 |
| 页结算 | 1 次（本页通过数 + 是否过闸门） | 每页，约每 20 词一次 |
| 轮次收尾 | 1 次（elapsed、累计通过数） | 每轮 |
| 逐词翻卡 / 自认 | **0 次** | — |

自认状态存在前端（内存 + sessionStorage，沿用 ladder 的 30min TTL 恢复先例，ADR-0036 §6）。
单卡路径上没有任何网络往返，<5s/词 的节奏约束因此**构造上**成立，而不是靠自觉。

### 4.4 为什么不复用 `l3_sessions`

它的形状是对的，但它的 `type` 枚举、service 声明边界、前端入口全部绑在 L3 子空间上
（`L3SessionService` 抽样的是 `context_id`，渲染的是语境）。让它同时承载"词书词表定格"
会让 ADR-0019 的边界注释变成谎话——`practice-loop-p0p1` §P1-1 拒绝把统一投影并进
`L3PracticeService` 时用的就是这个理由。**形状照抄，表分开。**

## 五、运行语义

### 5.1 创建

1. 入口：`ReviewPage` 模式选择区新增第 6 张卡「葫芦冲刺」，`onStart("hulu")` 不进 `ReviewSession`，
   走独立分支（与 `ladder`、`cram` 的分支方式一致，`ReviewPage.tsx` 已是这个结构）。
2. 必选：词书、考试日期、目标轮数。可选：direction、每页词数。
3. **创建前风险校验**（服务端也做一遍，不只前端）：
   `单轮预估天数 = ceil(词数 / 400)`，`需求 = 目标轮数 × 单轮预估`，超过 `exam_date - today` 即拒绝，
   返回缺口天数，提示降轮数或缩小范围。400 词/天是初始常量，放配置不写死在两处。
4. 若该词书已有 `active` 计划：返回现有计划而非新建（受唯一索引保护，重复提交安全）。

### 5.2 一轮之内

- 按 `word_ids` 分页，页大小取计划值。
- 词卡复用 L1 现有三层渲染（答案层 / 锚点层 / 网络层），**先只展示词头，答案层默认折叠**：
  回忆 → 翻开 → 自认过/不过（修正 3）。
- 页尾结算：`通过数 / 页词数 ≥ gate_ratio` 才放行。
- **未达标：整页自认清零，切回学习态（两层展开），不记录这次失败，不进入下一页。**
  不做"无限卡死"，也不做"错题回尾"——那是 cram 的机制（C3）。
- 允许回看已过的页，但不允许在回看时改写已结算页的结果。

### 5.3 轮与轮之间

- 一轮走完写 `hulu_rounds` 收尾行，**不安排任何复习、不生成任何到期**。
- 下一轮词集、词序与上一轮完全相同（第 4 条"不做什么"）。
- 轮次耗时按墙钟计算，中途退出再进入**累计**而不是重计：`elapsed` 在每次收尾时
  由各段 `ended_at - started_at` 求和。中断不超过当日的不切开。

### 5.4 缩时曲线（只读，且只读自己）

- 数据来源唯一：`hulu_rounds.elapsed_seconds`，按 `round_no` 排序。
- 展示三样：各轮天数、相对第一轮的降幅、剩余轮数与距考试天数。
- **必须同时展示免责声明**：缩时是代理指标，不是掌握证明
  （一手口径：BV1kJ4m1J7Tx `[07:41]`「虽然你背完之后可能还什么都记不住，但是那个天数在减少」）。
- 进行中的轮不进曲线（没有 `ended_at` 就没有柱）。
- 全局变强信号（基于 `review_logs` 的真实复习耗时趋势）**另行立项**，不在本计划范围，
  也不与本曲线共图。

### 5.5 结束与放弃

- 完成：`round_no = target_rounds` 的轮收尾时置 `status='completed'`。
- 放弃：随时可置 `abandoned`，保留已有轮次（曲线仍可看）。
- 两者都会在 `suspend_review=true` 时把本批词从 `suspended` 恢复（C6 的逆操作，必须自动发生，不能让用户手动收拾）。

## 六、与五个现有模式的边界（实现期不得越过）

| 模式 | 允许的代码关系 | 禁止的代码关系 |
| --- | --- | --- |
| `review` | 只读它的词书与词条；C6 开关复用 `forgetting.service` 的挂起/恢复 | 读或写 `review_logs`；改 queue 排序；在未开开关时让到期队列少词 |
| `cram` | 无 | 复用 `DrillSession` 的回尾队列；把葫芦未通过词塞进练习 |
| `preview` | 无 | 借用其"零写入"代码路径存耗时 |
| `zen` | 无 | 把 zen 的无限续载接进轮次 |
| `ladder` | 入口分支的写法照抄 | 复用其三轮结算或 `ladder_rung` |

模式清单不变量目前由 `reviewModesForTest()`（`ReviewPage.tsx:31`）锁定为
`["review","cram","preview","zen","ladder"]`。引入后应变为追加 `"hulu"` 的**恰 6 项**，
并保留「剥注释后源码不再含全局开关」那类断言的同等强度。

## 七、分期

每期都可独立合并、独立回退。

### P0 · 计划容器（后端，无 UI 或仅只读）

- 迁移：两张表、RLS、两个检查约束、部分唯一索引。
- `HuluPlanService`：创建（含定格 + 风险校验）、读取、放弃。**不含**翻卡。
- 未知 `plan` 版本拒绝（F2 的等价物：此处版本写在代码常量里，表上不必有 version 列，因为没有 JSON 计划体）。
- 测试：重复创建返回原计划；风险校验超限拒绝；跨用户 RLS；词书删除级联。

**验收**：服务测试全绿，且全库 grep 确认 `src/services/hulu*` 不引用 `review_logs` 与 `user_word_progress`。

### P1 · 一轮走完（前端 + 页/轮结算）

- `ReviewPage` 加第 6 个模式分支，新组件 `HuluSprintSession`，**不修改** `ReviewSession` 与 `DrillSession`。
- 遮答 → 翻开 → 自认 → 页结算闸门 → 轮收尾。
- 中断恢复走 sessionStorage（30min，沿用 ADR-0036 §6 的 TTL）。
- 组件测试：60% 被拦且不跳页、80% 放行、回看不改已结算页、刷新后续上。

**验收**：一轮能从创建跑到收尾；`review_logs` 行数在整轮前后不变（集成测试断言）。

### P2 · 多轮 + 曲线 + 冲刺开关

- 多轮滚动、累计耗时、曲线三要素与免责声明。
- `suspend_review` 开关：复用 ADR-0020 的挂起/恢复，计划结束或放弃时自动恢复。
- 开关默认关；开启前展示「这批词将暂时退出到期队列，计划结束后自动回来」。

**验收**：两轮之后曲线两点递减；开关开/关/自动恢复三条路径各有测试；`review` 队列在开关关闭时与现状逐词一致。

### 不做（除非单独立项）

- 日常复习的变强信号（§5.4 末段）。
- 按轮动态调整词集或词序。
- 词级通过历史、错题导出。
- 移动端离线（ADR-0023 本来就是 online-first，无离线同步）。

## 八、风险与对策

| 风险 | 表现 | 对策 |
| --- | --- | --- |
| 轮数不够，批内词等不到第二次 | 用户按警告被拒后仍强行降轮数硬建 | 风险校验只**警告性拒绝极端情况**（需求 > 2× 剩余天数），中间地带放行但在计划页持续显示缺口。不替用户做主 |
| 自认放水使 80% 失真 | 用户不回忆直接全标通过，曲线变好看但没有检索 | 接受。闸门是行为设计不是防作弊；强校验会把流程拖回 cram。曲线旁的免责声明就是为这个局限而存在 |
| 挂起开关与一键遗忘互相覆盖 | 两者都写 `state='suspended'`，分不清是谁挂的 | 复用 ADR-0020 时**只挂计划词集内、且当前非 suspended 的词**，并在计划行记录挂起清单；恢复时只恢复清单内的词，不动用户自己挂起的 |
| 定格词集过大 | 一个计划上万 uuid | `word_ids` 上限 20000；页结算只传计数不传明细，请求体与词数无关 |
| 客户端时钟不准导致耗时异常 | 负耗时或数天的单轮 | `elapsed_seconds` 服务端夹取到 `[0, 86400×单轮]`，超界记到上限并打标记，不拒绝提交（拒绝会丢轮次） |

## 九、测试与回归防线

1. **模式清单锁定**：扩展现有 `reviewModesForTest` 断言到恰 6 项，顺序固定，`"hulu"` 在末位。
2. **分支不可达**：源码级断言 `ReviewSession` 与 `DrillSession` 不出现 `hulu` 字符串（照抄 ladder 那条「剥注释后不含 `isLadderModeEnabled`」的做法）。
3. **零写入**：集成测试在一轮前后比较 `review_logs` 与 `user_word_progress` 的行数和 `updated_at` 最大值。
4. **闸门**：页通过率 0.79 拒绝、0.80 放行（边界用 `gate_ratio` 列值，不写死 0.8）。
5. **唯一性**：同词书并发双创建只有一个成功，另一个拿到同一计划。
6. **恢复**：挂起清单恢复后，用户在计划期间**手动**挂起的词仍保持挂起。
7. **级联**：删词书 → 计划与轮次消失；删单个词 → 计划仍在，渲染时只缩不换。
