## 二、目标行为（以原型为准）

原型 `deliverables/hulu-sprint-prototype-2026-10-06.html` 已用 DOM 桩 33 项断言锁过。
设计稿与原型冲突时，**以本文为准**，并回头改原型，不在实现里私自调和。

一条计划的生命周期：

```
创建（定格词集、校验风险）
  → 第 n 轮开始（记起始时刻）
      → 逐页：遮答 → 翻开 → 自认 → 页结算
            通过率 < gate → 整页清零，退回学习态，不入库
            通过率 ≥ gate → 记一笔页结算，进下一页
      → 允许回看已结算页，不允许改结果
  → 第 n 轮收尾（记真实耗时）
  → 未到目标轮数：不生成任何复习，直接进下一轮
  → 到目标轮数：计划完成
  → 任何时刻可放弃：已有轮次保留
```

创建时的风险三级（原型里的 `assessRisk`）：

| 条件 | 结果 |
| --- | --- |
| 未填考试日期，或日期已过 | 拒绝 |
| `目标轮数 × ceil(词数/400)` > 剩余天数 × 2 | 拒绝 |
| 只是大于剩余天数 | 放行，但计划页持续显示缺口 |
| 其余 | 放行 |

400 词/天是**初始常量**，放一处配置。它不是测量值，审查时不要把它当成承诺。

## 三、数据模型

### 3.1 `hulu_plans`

| 列 | 约束 | 为什么这样 |
| --- | --- | --- |
| `id` | uuid pk | |
| `user_id` | FK → profiles，RLS `auth.uid() = user_id` | 与 `sessions`、`l3_sessions` 同形态 |
| `wordbook_id` | 复合 FK `(wordbook_id, user_id)` → `wordbooks(id, user_id)`，级联删 | 照 `sessions_wordbook_owner_fkey` |
| `direction` | `通用/考研/雅思` 或空 | 复用既有方向枚举，只做标记，不参与抽样 |
| `exam_date` | date，**非空** | 没有截止日期就不是葫芦的适用场景 |
| `target_rounds` | smallint，2..8，默认 4 | |
| `page_size` | smallint，5..50，默认 20 | 原型用 4 是为了走得完，不是默认值 |
| `gate_ratio` | numeric(3,2)，0.50..1.00，默认 0.80 | 存下来，避免调参要迁移 |
| `word_ids` | uuid[]，`cardinality` 在 1..20000 | **创建时定格**，之后词书变动不影响 |
| `status` | `active / completed / abandoned` | |
| `suspend_review` | boolean，默认 false | 见 §五，默认关是有意的 |
| `started_at / ended_at / created_at` | timestamptz | |

部分唯一索引：

```sql
CREATE UNIQUE INDEX idx_hulu_plans_one_active
  ON hulu_plans (user_id, wordbook_id)
  WHERE status = 'active';
```

形状学 `idx_sessions_one_active`，但谓词用 `status` 而不是 `ended_at`，
因为计划的结束是业务状态，不是一次坐次的结束。

### 3.2 `hulu_rounds`

| 列 | 约束 |
| --- | --- |
| `id` | uuid pk |
| `plan_id` | FK → hulu_plans，级联删 |
| `user_id` | 冗余，RLS 用；复合 FK `(plan_id, user_id)` 防止挂到别人的计划 |
| `round_no` | smallint，`UNIQUE (plan_id, round_no)` |
| `started_at` | timestamptz，客户端上报 |
| `ended_at` | 可空 = 进行中 |
| `elapsed_seconds` | integer，收尾时写入，之后不改 |
| `pages_passed` | smallint |
| `words_passed` | integer，一轮内一词只计一次 |
| `words_total` | integer，冗余 `cardinality(word_ids)`，计划删了曲线仍读得懂 |

### 3.3 刻意没有的表

- **没有页级明细表。** 页结算只是计数加一。失败的页不留记录。
- **没有词级通过记录。** 留了就会有人想把它接进错题库。葫芦的「没通过」是页级比例事件，
  不是词级错题（ADR-0019 §1 的错题库是 `attempts(outcome='wrong')` 的派生视图）。
- **没有 `plan jsonb`。** 词集直接是 `word_ids` 列，不需要版本化的计划体。
  因此 `l3_sessions` 那套「非法 version 拒绝恢复」在这里用不上，不必照搬。

### 3.4 迁移

编号 **0050**，目录 `drizzle-release/`（V8 确认 0049 是当前最新）。
只新增表、索引、RLS、检查约束，**不改任何已有表**。这是可行性上最有利的一条：
回退 = 删两张表，不存在数据搬迁。

## 四、写入时点

这是「L1 速刷不进会话」（V11）的解法，要求构造上成立，不靠约定。

| 时点 | 写入 | 次数 |
| --- | --- | --- |
| 创建计划 | `hulu_plans` 一行 | 1 |
| 轮次开始 | `hulu_rounds` 一行，`ended_at` 空 | 每轮 1 |
| 页结算通过 | 当前轮的 `pages_passed` 加一 | 每页 1 |
| 轮次收尾 | 填 `ended_at`、`elapsed_seconds`、`words_passed` | 每轮 1 |
| 逐词翻开、逐词自认 | **无** | 0 |

自认状态放前端内存，加 sessionStorage 兜底。TTL 沿用 ADR-0036 §6 的 30 分钟。
超时丢失的代价是**重走当前未结算页**，不是损坏计划——因为未结算页本来就没入库。

耗时由客户端上报起止时刻，服务端只做夹取：`elapsed_seconds` 限制在
`[0, 86400 × 允许的最大单轮天数]`。超界记到上限并打标记，**不拒绝**。
拒绝会让用户丢掉一整轮。

## 五、与一键遗忘的关系（本节是审查重点）

V7 的 `ForgettingService` **不能直接调用**。原因：

- 它的 `restore` 按 `batchId` 回写**快照里的原 state**。葫芦如果走它的 apply，
  就要给每个词造锚点确认、写它的批次日志，还要保证冲刺期间用户自己的一键遗忘
  不会和这个批次互相覆盖。耦合远超收益。
- 它的 apply 语义是「非锚点全挂起」。葫芦要的是「**这一批词**挂起，其他词不动」，
  方向相反。

所以葫芦的挂起是**自己的最小实现**，只做两件事：

1. 开启时：对 `word_ids` 中当前 `state` 不是 `suspended` 的行置 `suspended`，
   并把这些 id 记进计划自己的清单（建议列 `suspended_word_ids uuid[]`，可空）。
2. 计划完成或放弃时：只把清单里的行恢复到 `review`，**清单之外的不动**。

由此保证：冲刺期间用户手动挂起的词，结束后仍保持挂起。

`suspend_review` 默认 **false**。打开前前端必须明示
「这批词会暂时退出到期队列，计划结束或放弃时自动回来」。
不做「检测到在冲刺就自动暂停 review」——那是 ADR-0036 §4 已经否决过的静默接管。

这一列和这两步是**可整段删除**的。如果审查认为不值得，删掉后设计稿其余部分不变，
C6（同一批词被两套系统追）改记为「已知、不处理」。这是 §八 里唯一的可选项。

## 六、接口形状（建议，不是契约冻结）

全部新增，不改既有端点。前缀 `/api/hulu`。

| 方法 | 路径 | 作用 | 幂等 |
| --- | --- | --- | --- |
| POST | `/api/hulu/plans` | 创建。同词书已有 active 计划则**返回那个计划**，不报冲突 | 是 |
| GET | `/api/hulu/plans/:id` | 读计划 + 轮次 | 是 |
| POST | `/api/hulu/plans/:id/rounds` | 开始下一轮。已有未收尾的轮则返回它 | 是 |
| POST | `/api/hulu/plans/:id/rounds/:no/pages` | 页结算。同一页重复提交不重复计数 | 是 |
| POST | `/api/hulu/plans/:id/rounds/:no/finish` | 收尾 | 是 |
| POST | `/api/hulu/plans/:id/abandon` | 放弃 | 是 |

幂等是硬要求：页结算和收尾都可能被网络重试打两次，重复计数会让曲线失真。

服务端再做一次风险校验，不信任前端。校验失败返回缺口天数，不返回 500。

## 八、可行性裁决

按「什么会让它不可行」排列，而不是按乐观路径。

### 8.1 现在就可以判定为可行的

- **回退成本**。只加表和端点，不改已有表。判错了删掉即可。
- **与 FSRS 的隔离**。新表没有 stability / due 列，服务层不引用 `review.service`。
  可被测试证明，不是约定。
- **模式入口**。V1 的清单是纯常量，加一项不触碰其余分支。V9 的测试形式可以直接扩展。
- **词集定格**。`word_ids uuid[]` 加 20000 上限，页结算只传计数，请求体与词数无关。

### 8.2 有条件可行（审查时要确认条件还在）

- **挂起的最小实现**（§五）。条件是 `user_word_progress.state` 确实可以被
  计划服务按词集更新，且不触发 `ForgettingService` 的批次日志副作用。
  如果 `state` 的写入被收口到唯一一个仓库方法里，就调用那个方法；
  如果散落各处，先停下来，不要新增第三处写入。
- **sessionStorage 恢复**。条件是 30 分钟 TTL 的先例（ADR-0036 §6）仍是前端会话恢复的统一做法。
  如果已经换成别的机制，葫芦跟着走，不单独发明。
- **只读词条接口**能一次取回一页所需字段。如果取一页要打 20 次请求，
  就违反了 §四「逐词零请求」的精神，需要先有批量读取再做 P1。

### 8.3 不可行、必须改设计的信号

审查中如果发现下面任何一条，停下来改设计稿，不要在实现里补丁：

1. `review` 的队列构建**无法**在不改其代码的前提下排除一批词。
   —— 那么删掉 `suspend_review`，接受两套系统并行。
2. 前端词卡组件**无法**在不含评分按钮的形态下复用，而且新写只读卡面需要复制大量逻辑。
   —— 缩小范围：P1 只做纯文本卡，不复用三层渲染。
3. 新增端点触发了 OpenAPI breaking 门禁。
   —— 不应该发生（只加端点）。如果发生，说明生成流程把「新增」也判成破坏，先查门禁口径。
4. `word_ids` 定格与「词书是活的」这一产品预期冲突，用户不能接受冲刺期间加的词进不了计划。
   —— 这是产品裁决，不是技术问题。默认保持定格（理由见实现计划：开卷后加题会静默变卷）。

### 8.4 明确不做，所以不算可行性风险

日常复习的「变强信号」、按轮调整词集、词级通过历史、离线可用。
都不在本期。不要为它们预留字段。

## 十、测试（审查时核对这些断言写得出来）

1. 模式清单恰为 `["review","cram","preview","zen","ladder","hulu"]`，顺序固定。
2. `ReviewSession.tsx`、`DrillSession.tsx`、`LadderReviewSession.tsx` 源码不含 `hulu`。
3. 一轮前后，`review_logs` 行数与 `user_word_progress.updated_at` 的最大值都不变。
4. 页通过率 `gate_ratio - 0.01` 被拒，`gate_ratio` 放行。用列值，不写死 0.8。
5. 同词书并发两次创建，只有一个 `active` 计划。
6. 页结算重复提交两次，`pages_passed` 只加一。
7. 挂起恢复后，计划期间**用户自己**挂起的词仍是 `suspended`。
8. 删词书，计划与轮次级联消失。删单个词，计划还在，渲染时只缩不换、不补词。
9. `elapsed_seconds` 为负或大到离谱时被夹取，轮次不丢。

第 3 条和第 7 条是这张设计稿的核心。它们写不出来，说明设计在那个点上不成立。

## 十二、一句话
