## 一、两个决策点（已按推荐答案定稿；推翻需主控明说）

### D1 「处置 B」的形态：**账本对账工具化**，不改已发 SQL

- 推荐（定稿）：**不改 0048/0049 的 SQL**。理由：
  1. drizzle 迁移是**线性一次性**设计，存量生成类迁移大多非幂等 —— 改两条没有原则边界，改全部等于重写历史；
  2. "账本缺行"的库的真正病因是**账本不是真源**（schema 被 push 改过了），正解是把**账本对账工具化**（报告 + 采纳），而不是让 SQL 假装能重跑；
  3. 修复成本差异巨大：一条 INSERT vs 打开「改已发迁移」的先例。
- 反选项（仅当主控明选）：0048/0049 语句补 `IF NOT EXISTS`/`DROP+ADD` —— 安全（迁移器只按 `created_at` 判跳过、hash 不参与判定），但开创「改已发 SQL」先例。**默认不选**。

### D2 新迁移纪律：**0051 起一律手写 + DDL 幂等**，机器 lint

- 推荐（定稿）：新迁移手写，DDL 幂等（`IF NOT EXISTS` / `DROP ... IF EXISTS` + `ADD`），与 0021/0023/0024/0028/0047/0050 的手写线一致；
- `drizzle-kit generate` 只用于**产快照与校验**（链已愈合，no-op 守卫在跑）；若用它产迁移，**入库前必须人工改写为幂等**；
- 机器化：`verify-schema-drift` 加幂等 lint，cutover = **0051**（见 G3）。

## 二、任务分解

### G0 · dev/prod 账本对账与解锁（手工，立即；外派按 §四 T0 执行）

目标：把 dev 库的 0049 账本行补上，然后让 0050 正常落下，验证葫芦两表。

1. **只读体检**（先跑，输出进汇报）：
   `select count(*)::text, max(created_at)::text from vocab_migrations.__v2_release_migrations;`
   `select count(*)::text from information_schema.columns where table_name='l3_contexts' and column_name in ('translation','translation_src');`
2. **补账本行**（带守卫，幂等）：
   ```sql
   INSERT INTO vocab_migrations.__v2_release_migrations (hash, created_at)
   SELECT '86043e8a3822e526c23112908597ccbc0a20729050b572cc285c731f87593ae1', 1790405138090
   WHERE NOT EXISTS (
     SELECT 1 FROM vocab_migrations.__v2_release_migrations WHERE created_at = 1790405138090
   );
   ```
   （hash = `Get-FileHash -Algorithm SHA256 drizzle-release/0049_l3_contexts_translation.sql`，与 drizzle 同文件口径；仅为账本完整，迁移器只用 created_at 判跳过。）
3. **跑迁移**：`docker compose -f compose.dev.yaml start migrate`（重启 one-shot），或 `DATABASE_URL=<dev> npm run db:migrate`。
4. **验证**：`to_regclass('public.hulu_plans')`、`to_regclass('public.hulu_rounds')` 非空；账本行数 = journal 条目数（当前 51）。
5. **prod/其他库**：同口径先查后治；把体检输出贴进汇报，由主控决定是否同法处置。

### G1 · 账本对账工具（`scripts/reconcile-migration-ledger.ts` + 单测）

照 `scripts/adopt-release-baseline.ts` 的形制（pg Pool + fs/crypto，无新依赖）。

- `report`（默认，只读）：逐条输出 journal 条目状态：`applied (exact when)` / `applied (different when)` / `missing`；尾部打印 `max(created_at)` 与 missing 计数。退出码恒 0（报告用途）。
- `adopt --to <tag|idx> [--write]`：对 ≤ 目标且 missing 的条目，生成并（`--write` 时）执行
  `INSERT INTO vocab_migrations.__v2_release_migrations (hash, created_at) SELECT $1,$2 WHERE NOT EXISTS (SELECT 1 ... created_at = $2)`；
  不带 `--write` 只打印将执行的语句（dry-run）。
- 导出纯函数供单测：`computeLedgerDiff(journal, appliedRows)`、`sha256File(path)`、`buildAdoptStatements(diff, target)`。
- 单测 `tests/scripts/reconcile-migration-ledger.test.ts`：exact/different/missing 三态、target 过滤、dry-run 不执行、`WHERE NOT EXISTS` 守卫文案、sha256 与文件一致。

### G2 · RLS 验收断言加固（`scripts/run-rls-acceptance-migrations.ts`）

- 读完迁移后，读 `drizzle-release/meta/_journal.json`：
  - `migrationCount === journal.entries.length`（替换 `migrationCount < 1`）；
  - `max(created_at) === max(entry.when)`（再补一条：静默跳迁移的双保险）；
  - 保留 `auth.uid()` 与 `relrowsecurity` 既有检查。
- 单测：把「计数/最大值比较」抽成纯函数 `expectedJournalTail(journal)`，用假 journal 测断言。

### G3 · 纪律落地：ADR-0042 + 幂等 lint + 设计稿归档（可选）

**G3-a ADR-0042**（`docs/adr/0042-migration-chain-governance.md`）：
标题：迁移链治理 —— journal 严格递增 / 快照链 / 账本真源 / 新迁移幂等。Decision 六条：
1. 账本（`vocab_migrations.__v2_release_migrations`）是唯一真源；**不指望重放已应用迁移来自愈**；
2. journal `when` 严格递增 + 字段齐备（已有机器守卫）；
3. 快照链必须闭合到最新（已有 generate no-op 守卫）；
4. **新迁移（0051 起）一律手写 + DDL 幂等**；generate 产物入库前必须改写为幂等；
5. 账本缺行（schema 被 push/手工改过）→ 用 `reconcile-migration-ledger` 对账，**不改已发 SQL**；
6. RLS 验收的完成判据 = 账本行数与 journal 条目数一致（G2 已机器化）。

**G3-b 幂等 lint**（挂进 `scripts/verify-schema-drift.ts`）：
- cutover 常量 `MIGRATION_IDEMPOTENCY_CUTOVER_IDX = 51`；只扫 `NNNN_*.sql` 且 `NNNN ≥ 51`。
- 逐 `--> statement-breakpoint` 语句检查，命中即 fail：
  - `ADD COLUMN` 无 `IF NOT EXISTS`；
  - `CREATE (UNIQUE )?INDEX` 无 `IF NOT EXISTS`；
  - `CREATE TABLE` 无 `IF NOT EXISTS`；
  - `ADD CONSTRAINT` 且同文件无同名 `DROP CONSTRAINT IF EXISTS`；
  - `CREATE POLICY` 且同文件无同名 `DROP POLICY IF EXISTS`；
  - `CREATE TRIGGER` 无 `DROP TRIGGER IF EXISTS`。
- 豁免：语句前一行注释 `-- @idempotency-waive: <理由>`（数据回填 UPDATE/INSERT 等）。
- 报错文案必须写明「改法」：给对应幂等写法的样板。
- 单测：0050 全绿（正向）、0049 式样被拦（反向）、waiver 生效、cutover 生效。

**G3-c 设计稿归档（可选，主控可删）**：把 `docs/design/` 下 10 份未跟踪稿
（葫芦背书法 ×6、hytidelegend ×4）`git add` 提交（**只 add，不改内容**），并入治理提交或单独 `docs(design):` 提交。
