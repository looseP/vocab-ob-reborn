## 一、P0 · 计划容器（后端，无 UI）

**目标**：迁移 0050 + `HuluPlanService` 的创建/读取/放弃 + 风险校验 + 幂等创建。不含翻卡、不含轮次交互、不含挂起执行。

### P0-0 立 ADR（先写，后动工）

新建 `docs/adr/0041-hulu-sprint-plan-container.md`（编号顺延，最新为 0040）。骨架：

- **Status**: Accepted；**Date**: 2026-10-06
- **References**: ADR-0004 §6、ADR-0005、ADR-0019 §2（L1 速刷不进会话）、ADR-0020（遗忘=挂起+快照回写先例）、ADR-0036 §4 修订（显式模式）、完备设计
- **Decision**：
  1. 葫芦 = L1 词书上的阶段性冲刺计划；独立两表（`hulu_plans`/`hulu_rounds`），不进 `sessions`、不进 `l3_sessions`；
  2. 零 FSRS 写入为结构性保证（表无 FSRS 列、服务不引用 review.service）；
  3. 显式第 6 个复习模式，不选则分支不可达；
  4. 词集创建时定格（`word_ids uuid[]`），只缩不换；
  5. 可选挂起开关（默认关）：自研最小实现，`ReviewRepository` 两个新方法 + 计划行快照，**不复用** `ForgettingService` 的批次日志；恢复 = 快照回写；
  6. 会话恢复走 localStorage + 24h + 独立前缀（沿用现行机制，ADR-0036 §6 的 30min 文本以代码现状为准）。
- **Consequences**：回退 = DROP 两表；stale active 计划的挂起词不自动过期（计划页提示，见 P2-4）。

### P0-1 术语注册（`CONTEXT.md`）

注册三个术语，各带 `_Avoid_`：

- **葫芦冲刺 (Hulu Sprint)**：挂在 L1 词书上的阶段性多轮冲刺计划……_Avoid_: 把它说成"更好的复习方式"；塞进 sessions/l3_sessions；写 FSRS
- **轮次 (Hulu Round)**：一次整批过词的起止……_Avoid_: 与 review 的"会话/坐次"混用
- **缩时曲线**：各轮墙钟耗时的柱状序列，代理指标非掌握证明……_Avoid_: 推广到 review；用词数/通过率反推耗时

### P0-2 domain 纯函数与类型（`src/domain/hulu-sprint.ts`，新建）

- 常量：`HULU_WORDS_PER_DAY = 400`、`HULU_MAX_SINGLE_ROUND_SECONDS = 7 * 86400`、`HULU_MIN_ROUNDS=2 / MAX_ROUNDS=8 / MIN_PAGE=5 / MAX_PAGE=50 / MIN_GATE=0.5 / MAX_GATE=1 / MAX_WORDS=20000`。
- 纯函数：`assessHuluRisk({ wordCount, targetRounds, leftDays, wordsPerDay }) → { perRound, need, left, level: "ok"|"warn"|"block" }`；`huluGateDecision(passed, total, gateRatio) → "pass"|"block"`（total≤0 → "pass"，供删空页自动通过）；`clampElapsedSeconds(seconds, max)`。
- 类型：`HuluPlanRow` / `HuluRoundRow` / `HuluPlanWithRounds` / `HuluRiskResult` / `HuluPagePayload`。
- domain 保持零出向（不 import db/repositories/zod）。
- 单测：`tests/domain/hulu-sprint.test.ts` —— 风险三档边界（含 2× 边界）、闸门边界（列值）、夹取。

### P0-3 schema 与迁移 0050

### P0-4 仓库层

### P0-5 服务层（`src/services/hulu-plan.service.ts`，新建）

- 依赖注入照 `ForgettingService` 形状（`txRunner` / `repositoryFactory` 可选注入）。
- `createPlan`：单事务内 ① 校验词书归属 → ② `findActivePlanByWordbook`，有则直接返回（幂等）→ ③ `listWordIdsByWordbook` 定格 → ④ `assessHuluRisk`，block 则抛 `BusinessRuleError`（422，携带 `{ need, left, perRound }`）→ ⑤ 插行（唯一索引兜底并发；撞唯一索引则重查返回既有计划）。`suspendReview = true` 在本期**拒绝**（`ValidationError("HULU_SUSPEND_NOT_YET")`），P2 开放。
- `getPlan`（计划+轮次）、`abandonPlan`（active→abandoned；已 abandoned 幂等返回；已 completed → 409）。
- 所有写路径 `withTransaction(..., { actorId: userId })`。
- 服务内**禁止**出现 `review_logs` / `user_word_progress` 字样（完备设计测试 10）。
- 单测：`tests/services/hulu-plan.service.test.ts` —— 幂等创建、并发撞索引、风险 block/warn、abandon 幂等、跨用户隔离。

### P0 验收 / 否决条件

## 二、P1 · 一轮走完（前端 + 页/轮结算）

**目标**：第 6 个模式可用，一轮能从创建跑到收尾；单卡路径零请求；现有五个模式与 FSRS 一个字节不差。

### P1-1 轮次与页端点

- service 增：`startRound`（计划行 `FOR UPDATE`；有未收尾轮返回它；round_no 超限 → 409）、`settlePage`（完备设计 R7 条件 UPDATE；服务端复算本页存活词数、复验闸门，422/409 语义）、`finishRound`（夹取 elapsed；末轮同事务 completed）、`getPlanPage`（R4：切片 → `repos.reviews.findWordsByIds` → 按切片序重排 → 契约裁剪字段）。
- routes/operations/契约同步补齐 4 条；openapi 再生。
- 测试：页结算幂等（重复提交只加一）、跳页 409、不过闸 422、轮次幂等、`alive=0` 自动通过。

### P1-2 前端会话组件

- `src/frontend/components/review/HuluSprintSession.tsx`（新建）：
  - 只读卡面（词头/音标/词性/释义/助记；答案层默认折叠）：遮答 → 回忆 → 翻开 → 自认过/不过。
  - 页尾结算：`< gate` → 整页清零回学习态（不发请求）；`≥ gate` → POST settle → 下一页。
  - 已结算页回看只读；进度指示（第 x/y 页 · 第 n/N 轮）。
  - localStorage 恢复（完备设计 R3）：键 `vocab:hulu:sprint:<planId>`，校验 planId/roundNo/TTL。
  - 轮收尾：POST finish → 展示本轮耗时。
- `src/frontend/pages/ReviewPage.tsx`：`reviewModes` 末位加 hulu；网格去掉 `xl:grid-cols-5`；渲染分支与 `ladder`/`cram` 并列。**不改** `ReviewSession`/`DrillSession`/`LadderReviewSession`/`useReview`。

### P1-3 测试

- 改 `tests/frontend/ladder-typing-reachability.test.tsx`：模式清单恰 6 项、hulu 末位。
- 新 `tests/frontend/hulu-reachability.test.tsx`：源码断言三个会话组件剥注释后不含 `hulu`；`ReviewPage` 含 `reviewMode === "hulu"`。
- 新组件测试（jsdom，照 ladder 测试的 DOM 桩做法）：60% 被拦不跳页、80% 放行（用 0.8 列值路径，不写死）、回看不改已结算页、刷新后续上、单卡路径零网络请求（mock `apiFetch` 计数）。
- 集成测试（`tests/` 下连库）：一轮前后 `review_logs` 行数、`user_word_progress.updated_at` 最大值不变（完备设计测试 3，suspend off）。

### P1 验收 / 否决条件

- 一轮能从创建跑到收尾；矩阵全绿。
- **出现以下任一情况，不进 P2**：集成测试里一轮前后 `review_logs` 行数有变化；单卡路径出现请求；三个既有会话组件源码出现 `hulu`。
- 回退：前端分支删除 + 端点保留（P0 仍可独立存在）。

## 三、P2 · 多轮 + 曲线 + 挂起开关

**目标**：多轮滚动、缩时曲线（带免责声明）、可选挂起开关全链路。

### P2-1 多轮与曲线

- 前端：轮与轮流转（finish → start 下一轮）；曲线组件（各轮耗时柱、相对首轮降幅、剩余轮数/距考天数 + 免责声明文案，文案含「代理指标，非掌握证明」与长中断说明）。
- 数据全部来自 `GET /api/hulu/plans/:id`（轮次列表），**禁止**任何前端推算耗时。

### P2-2 挂起开关接线

- service：`createPlan` 在 `suspendReview = true` 时，同一事务内 `bulkSuspendByWordIds` → 写 `suspend_snapshot`；`finishRound` 末轮 / `abandonPlan` 同事务 `restoreSuspendSnapshot` → 清快照。
- 前端：创建表单加开关（默认关）+ 明示文案；计划页显示挂起状态；`exam_date` 已过的 active 计划显示「考试日已过，建议放弃以恢复到期队列」横幅。
- 移除 P0 的 `HULU_SUSPEND_NOT_YET` 拒绝。

### P2-3 测试

- 完备设计测试 7（挂起/恢复四种 state 各一例 + 用户手动挂起不动 + 快照清空 + review_logs 零新增）。
- 测试 9（elapsed 夹取）。
- 曲线每个数字可回溯到 `hulu_rounds` 一行（组件测试断言数据源字段）。

### P2 验收 / 否决条件

- 两轮后曲线两点递减；开关开/关/自动恢复三条路径各有测试。
- **否决**：曲线上任何数字不能回溯到 `hulu_rounds` 的一行；挂起恢复动到快照之外的词。
- 回退：开关整段可撤（列与快照保留为空），不影响 P0/P1。
