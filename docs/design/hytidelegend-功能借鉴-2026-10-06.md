## 摘要

对方是一个**教育全流程工具箱**（记材料、备课、讲课、出题、批改、做播客、背图），vocab-ob 是一个**词汇学习系统**（词书、FSRS、L1/L2/L3 轨道、做题、作文）。

所以不是"功能比你少"，而是**分工不同**。我核实了 12 个候选功能，结论是：

- **2 个真缺口，且数据已经在库里**（复习日历、词表批量导入）—— 低成本高价值，建议立刻做
- **4 个明确空白，值得排期**（对话音频、能力路由、图像遮罩、助记图像）
- **3 个对方有但你不该抄**（艾宾浩斯排程、导师式授课的通用部分、手写答题卡）
- **2 个半成品可扩展**（挖空规则层、跨材料学习报告）

## P0-1：真实复习日历（数据已在库里，只差一个视图）

**对方有什么**：`applications/词汇星图` 的日历页展示"计划覆盖的日期与当日词表"，以及每页通过比例、当日完整排程。

**你有什么**：`src/services/stats.service.ts:17-21` 的 `ReviewForecast{dueNow, due7d, due14d}`，端点 `src/http/routes/review.ts:109`，前端 `DashboardPage.tsx:143` 有一张"未来 7 天预计复习"的卡片。

**问题**：`stats.service.ts:63-68` 的注释自己承认了 —— `due7d = dueToday * 1.5`，**这是估算值，根本没读 `user_word_progress.due_at`**。而 FSRS 明明已经为每个词算好了 `due_at`。

也就是说：**调度结果躺在数据库里，UI 在编一个假数字给你看。**

**为什么值得做**：这是"复习计划"的唯一入口。没有它，用户无法知道周三要复习什么，也就无法提前安排。FSRS 的排程优势（vs 固定艾宾浩斯）完全体现不出来。

**怎么做**：
- 新端点返回 `Array<{date, dueCount, sampleWords[]}>`，直接 `GROUP BY due_at::date`
- 日历视图（月或周），每格显示词数 + 通过率着色
- 点某天 → 跳到该日的 practice deck（你已有 `practice deck = 全部非 suspended 卡片`）
- 顺带删掉 `dueToday*1.5` 这个假算法，别留着误导

**成本**：低。一个 SQL 聚合 + 一个日历组件。**这是我最推荐先做的一个。**

## P0-2：词表批量导入（CSV / 纯词表）

**你有什么**：`POST /vocab-notes`（`src/http/routes/imports.ts:20-36`），`ImportPage.tsx:483` 只接受 `.md` / `text/markdown` + JSON 粘贴。CONTEXT.md 里提到的 `/imports/raw-text` 提案管线**未实现**。

**缺口**：
- 没有 CSV 导入（而 HytideLegend 的 `build-word-entry` 明确支持 `--format csv --word-column word --pos-column pos --meaning-column hint`，`skills/build-word-entry/SKILL.md:16`）
- 没有"纯词表 → 批量建 stub"这条最短路径

**为什么值得做**：你的 `F:/dev/vocab-ob/typewords-dict` 目录说明你手上是有成规模词表数据源的。现在建一个词要一次 L3 圈记，建 500 个词的成本高得离谱。**而 stub entry 机制你已经有了**（CONTEXT.md 定义得很清楚：`definition_md = ''`，不进复习队列），缺的只是批量入口。

**怎么做**：
- 接受 CSV / txt（一行一词）/ JSONL 三种格式
- 全部走 **capture-first**：建 stub + 进 L3，不做稳定性门禁
- 导入后返回 `created / existed / failed` 计数，失败的给原因
- 已有词表要能**增量补齐**（第二次导入跳过已存在的）

**成本**：低。你的 L3 stub 路径已经通了，只是没有批量壳。

## P1-1：材料 → 双角色对话音频（听力材料生成）

**对方有什么**：`skills/create-dialogue-podcast` 把一整篇书面文章**重写为"甲问乙答"的对话逐字稿**，再用两个不同音色 TTS 合成 MP3。关键在于：**内容被改写成了对话**，不是把原文朗读一遍。

**你有什么**：TTS 侧其实很完整 —— `reviewFlow/audioEngine.ts`、`AcousticAnchor.tsx:19`（波形）、`SpeakButton.tsx`。L3 source 的音频模型也已经建模（CONTEXT.md「Audio article media modeling」）。

**缺口**：只有"读单词/读句子"，没有"把一份材料变成听力材料"。`context_type='dialogue'`（`src/db/schema.ts:985`）只是语料分类标记，不是生成链路。

**为什么值得做**：考研和雅思都有听力/口语。**你已经有 L3 素材空间（真实文章、真题、口语原文）**，缺的只是把它变成"能听的版本"。而且这个功能有一个天然的应用场景：**长难句听写** —— 把 Text2 的一篇阅读文章转成对话音频，做精听。

**怎么做**（分两步，别一次做完）：
1. **先只做「逐字稿」**：L3 source → 结构化对话脚本（问/答分段，每段带 source 定位）。这一步价值就有 —— 用户可以先看文本版对话，检验"改写得对不对"，不用等音频。
2. **再做 TTS 合成**：两个音色分角色。你已有 TTS 通道，主要是把逐字稿按 speaker 切分、分别合成、按间隔拼接。**这一层随时可以交给 WorkBuddy 的能力做，不一定要写进服务端。**

**成本**：中。内容改写这一步需要 Agent 参与（不是确定性代码），跟你现有的 agent 提案管线是同一个模式。

**注意**：HytideLegend 这一步是**独立 skill**，不绑定任何学习系统。你可以照搬功能形态，但**别把它的父子 skill 嵌套结构搬进 vocab-ob**。

## P1-2：能力路由（功能多了以后必须有的东西）

**对方有什么**：`skills/htd-ai-augmented-education` —— 你描述一个任务，它告诉你该调用哪些 skill、按什么顺序、给出可复制的调用示例。核心是 `task_routing` 模式（`SKILL.md:46-52`），并有一条硬规则：**现有能力做不到时，`skill_sequence` 保持为空并在 `uncovered_requirements` 里说明局限，不许推荐看似相关但做不到的能力**。

**你有什么**：没有。功能已经有 11 个 ADR 族、30+ 端点族、多个 workspace（词书页、复习页、词条页、L3 书架/阅读视图/错题库/待录面、试卷台、写作工作区、学习笔记）。`OmniPalette.tsx` 是命令面板跳转，不是任务引导。

**为什么值得做**（两个层面，价值不同）：

**对用户**：新用户打开一个功能密度这么高的系统，不知道从哪开始。这是 onboarding 缺口。

**对 Agent（更值钱）**：你的 MCP bridge 现在是单点工具（`scripts/run-mcp-server.mjs:206 build_l2_prompt`）。Agent 拿到 vocab-ob 之后，面对 30+ 端点，**不知道该用哪个、什么顺序**。一个"任务 → 端点序列"的映射表，对 agent 的实际可用性提升可能比任何新功能都大。

**怎么做**（轻量版，别做重）：
- 一份 `capability-map.json`：任务类型 → 端点序列 → 前置条件
- 给 MCP bridge 加一个 `suggest_workflow(taskDescription)` 工具
- 前端首屏放一个"你想做什么"入口，命中后给 2-3 个候选路径

**成本**：低-中。是数据工作，不是逻辑工作。

## P1-3：葫芦背书法（深度解析 · 含一手资料核对）

> 这一节重写过。第一版我只看了 HytideLegend 的实现就下了结论，后来在
> `F:/v4kb-notes` 找到了原始视频转录稿（B站 BV1kJ4m1J7Tx）和加工笔记，
> 核对后发现：**HytideLegend 抄漏了葫芦最核心的一半。**

### 一、葫芦到底是什么（一手口径）

UP 主自创，把记忆比赛里的策略迁移到背书。原始场景是**考研 8 本法硕专业课书**。

他在 `[06:16]` 自己点明了两个核心特征：

> 「因为它有两个最核心的特征
> 　就是**一本书连背四遍**，就不是一本背完一遍换下一本
> 　然后第二个核心点就是**每一个点都是当场会复述就跳过**
> 　第二天不用复习，当天晚上也不用复习
> 　通过刷遍数一遍又一遍来复习」

展开就是 **4+4 滚动**：

| 阶段 | 做法 | 结果 |
| --- | --- | --- |
| 前四轮 | 一本书**连续背 4 遍**（从头背到尾，中间不复习），再换下一本 | 8 本 × 4 遍 |
| 后四轮 | 一本书背 1 遍就换下一本，跨书滚 4 轮 | 再加 8 本 × 4 遍 |

合计每本 8 遍。他本人最后背到 9.5 轮，第九轮一本只要 4 小时。

**「不复习」的确切含义**（容易被误读）：不是不重复，而是**不插入细粒度的回顾**。
他的原话是「从头背到尾完整背一遍，也叫重复」——**刷遍数本身就是复习形式**。

### 二、为什么连背四遍：一个行为燃料的设计

这是葫芦真正的创新，也是全篇最值钱的一段（`[07:41]-[08:54]`）：

> 「你第一遍从头背到尾只用 10 天，第二遍可能只用 8 天，第三遍 6 天，第四遍 5 天……
> 　你第四遍背完的时候就会非常开心，因为你知道自己每一遍都越来越快。
> 　**虽然你背完之后可能还什么都记不住，但是那个天数在减少，这个就是正反馈。**」

请注意这句话的分量：**「虽然什么都记不住，但天数在减少」**。

他在做一个**指标替换**：

| | 可观测性 | 短期表现 |
| --- | --- | --- |
| 「我记住了多少」 | ❌ 测不准，背完当天你也说不清 | 长期才能显现 |
| 「我背完一遍要几天」 | ✅ 每天在变、单调递减 | 立刻可见 |

**把不可观测的目标，换成可观测的代理指标** —— 这才是「连背四遍」存在的全部理由。
四遍不是为了四遍本身，是为了让你有四次机会看见自己在变快。

配套的还有一句反直觉的话（`[08:54]-[09:02]`）：

> 「背书的时候**不要关注你第二天能不能想起来**，你过一周能不能想起来，这个根本不重要。
> 　你只需要做到考研那一天能写出来就可以了。」

### 三、学术拆解：它不是算法之争，是调度粒度之争

这一层来自笔记第 9 节（整理者分析，非视频内容），我认为是整份材料里最有价值的部分。

**第一步，把「告别艾宾浩斯」翻译准确**：

- 艾宾浩斯式复习 = **细粒度调度** —— 每个材料配一条逐日回顾的日历
- 葫芦背书法 = **粗粒度调度** —— 以整本书为最小单位滚动，轮与轮之间天然形成长间隔

**第二步，组件逐条对照学术镜像**：

| 葫芦的组件 | 学术对应物 | 证据 |
| --- | --- | --- |
| 当场复述 80% | 检索练习 / 测试效应（主动提取强于重读） | **强** |
| 一本书连背四遍 | 过度学习 overlearning（边际收益递减） | **强** |
| 轮与轮之间的整轮间隔 | 间隔效应（分散优于集中） | **强** |
| 前四轮「不回头」 | 调度粒度之争：单本内属集中练习，需总轮数托底 | 条件性 |
| 缩时曲线 | 可观测进度 → 自我效能；但「缩时 = 掌握」无直接研究 | 经验 |
| 「记忆的本质是重复」 | 重复必要非充分，还取决于编码深度 | 条件性 |
| 神经突触通俗类比 | LTP 方向的通俗表述 | 需修正 |

**结论**：葫芦**保留了记忆研究里证据最硬的两条原理**（检索练习 + 间隔效应），
它改变的只是「复习在什么时候发生」的粒度与体验。

**笔记给的风险点**（我认为必须一起抄过来）：

> 粗粒度调度的安全感来自「还能滚很多轮」。
> **如果时间预算只够 4 遍上下、又完全不回头，单本内部的章节可能迟迟等不到第二次唤醒。**

**以及可混合的口径**：「不复习」是方法纯度，不是宇宙定律。
可以用整书滚动当宏观骨架，用艾宾浩斯式检查当抽检工具。

### 四、HytideLegend 抄了形，漏了神

核对完一手资料后，它的实现残缺得很明显：

| 葫芦的组件 | HytideLegend 实现了吗 |
| --- | --- |
| 不复习（不插入细粒度回顾） | ✅ Schema 强制 `review_item_ids.maxItems = 0` |
| 当场复述 80% 门槛 | ✅ `if (5 * passed < 4 * visible)` |
| **4+4 滚动（连背四遍再换下一本）** | ❌ **没有** |
| **缩时曲线（天数缩短作为进度指标）** | ❌ **没有** |

它的排程（`utils/scripts/hulu_schedule.py`）是**每天一批新词，走完一遍就结束了**，
下一轮靠用户手动开。也就是说：它拿到了「不复习」和「门槛」这两个**最容易被抄走的表层规则**，
把**「滚动结构」和「缩时作为行为燃料」这两个真正的核心**留在了原视频里。

还有一个**对象错配**：葫芦原设计针对的是「**多本大部头、考前一次性输出、考完就扔**」的材料
（8 本法硕专业课）。HytideLegend 把它用在了**单词**上——而单词恰恰是长期积累型材料。

> 有意思的是，笔记第 8 节做了一张对照表，指出**真正对标「一本词汇书」的不是葫芦，
> 是 CS 背书法**（畜生学习法 E8/E10）：十天十份、一日两次（早起新学 + 睡前复习）、
> 三种检查（一页 / 5 分钟 / 30 分钟）、两秒说不出就读三遍、每周一次整轮「筛子」。
> **如果你要做「考前突击背单词」，CS 比葫芦贴得多。**

### 五、对 vocab-ob 的修正结论

我上一版说「拿 80% 闸门」，这个结论**不够，也不够准**。修正如下：

**先说不该做什么**：

- ❌ 不要用葫芦**替代** FSRS。vocab-ob 是长期词汇积累，不是「考完就扔」的专业课书。
  在这个场景下 FSRS 的细粒度调度是对的。
- ❌ 不要把「不复习」搬进 L1/L2。你的间隔重复是优势，扔掉是倒退。

**再说该拿什么**（按价值排序）：

**① 缩时曲线 —— 这是 FSRS 完全缺失的反馈维度**

FSRS 给你 `stability`（记忆稳定性，天数），但用户**感知不到**它在涨：
每天打开都是一批到期词，永远在「还债」，没有任何「我在变强」的信号。

葫芦的解法可以原样搬：**统计每一轮 / 每一批词的完成耗时，画成递减曲线**。

- 这一批 500 词，第一轮用了 6 天，第二轮 4 天，第三轮 2.5 天
- 给用户看的是「你在变快」，不是「你的 stability 是 23.4 天」

这是**纯观测层**的改动：不动 FSRS 计算，不动调度，只增加一个统计与展示。
成本极低，且直接对冲「一键遗忘」要解决的问题 —— 用户在**中途**就能看见进展，
而不是攒到崩溃再一键重置。

**② 4+4 滚动结构 —— 放进攻坚包**

CONTEXT.md 定义攻坚包是「time-boxed cram plans with attempts recorded, no FSRS」。
**这就是 vocab-ob 里的葫芦位**。考前突击时：

- 材料总量固定（比如 5500 考研词）
- 有明确考试日期
- 冲刺期结束就不再高频维护

完全符合葫芦的适用条件。建议攻坚包支持「这一轮没过就再滚一轮」的滚动结构，
而不是现在的「练完拉倒」。

**③ 80% 门槛**（上一版已说，此处不变）
放攻坚包 / 首次学习 / 一键遗忘后恢复。别进 L1 速刷（破坏 <5s 节奏）。

**④ 顺带把风险也抄过来**
笔记那个风险点值得写进产品设计：**粗粒度调度必须有总轮数托底**。
如果只滚 1–2 轮就停，单批内部的词等不到第二次唤醒。
所以「滚动」必须配一个最低轮数提示，否则用户会半途而废且效果更差。

### 六、一句话

> 葫芦真正的发明不是「不复习」，是**把「我记住了多少」换成「我背完一遍要几天」** ——
> 一个可观测、单调递减、能天天给人正反馈的代理指标。
> **这个维度 FSRS 没有，且与 FSRS 正交。** 这是它最值得拿走的东西。

## P2-1：图像遮罩回忆（背图）

**对方有什么**：`applications/背图工具` —— 在图片上画矩形遮住部分内容，练习模式下点击循环显示/隐藏；支持两态（正常/隐藏）和三态（加提示）两种模式；可调矩形、缩放、旋转、描边、颜色。

**你有什么**：**没有**。全库无 `imageUrl` 字段，SVG 命中全是关系图画布（`L3GraphCanvas.tsx:56`），无遮罩组件。

**为什么值得做**（说清楚适用场景，别夸大）：
- **地图类**：中国地理分区、考研地理的地形区图 —— 常考"某区域是什么地形"
- **图表类**：经济学曲线、心理学图表
- **结构图**：英语长难句的句子成分树、语法结构
- **单词本身**：词形变化示意、一个单词在句子中的位置

**成本**：中。要做图片上传 + 画布 + 遮罩编辑 + 两态/三态练习。对方是独立小应用，摘出来做需要重新设计数据模型（图片存哪、遮罩坐标存哪、和 L3 source 怎么关联）。

**我的判断**：**先别做。** 这类需求在考研词汇场景里是"偶尔想起来"而不是"天天用"。如果你的 L3 里真的积累了地图/图表类材料，那时再做不迟。**放进 backlog 观察，不进当前排期。**

## P2-2：AI 助记图像（L1 三件套的第四条腿）

**对方有什么**：`skills/build-mnemonic-keywords` —— 一句知识 → 提取关键词 → 编联想场景 → **生成可直接喂给生图工具的完整提示词** → 确认后调 `/imagegen` 出图。它甚至要求 Agent 自评这个联想是 `good / weak / bad`，**牵强就明说"这个例子不适合用联想法"**。

**你有什么**：L1 的 Anchor tier（Tier 1）是 Prototype + Mnemonic，**纯文本的意象—助记对**（CONTEXT.md「Anchor tier」定义得很清楚）。没有图像。

**值得做吗**：取决于你用不用 WorkBuddy 这类带 ImageGen 的工具。
- 如果用 → 成本很低，就是在 L1 生成时多产一条 prompt，图片落到 outputs
- 如果不用 → 价值不大，文本意象已经够

**我倾向的做法**：不新建功能，而是在 `build-word-entry` 的 L1 生成里**增加一个可选字段 `image_prompt`**。用户想要图时自己拿去生成。**别在 vocab-ob 里建生图链路** —— 那不是学习系统的职责。

## P3：明确不建议抄的三个

### ❌ 艾宾浩斯固定间隔排程

对方有 `schedule-ebbinghaus-plan`（默认 `[1,2,4,7,15]`）。**你有 FSRS，FSRS 在这个维度上全面更优。** 抄过来是倒退。

但注意区分：**对方排程的价值不在算法，在"排程结果要给人看"** —— 这正是 P0-1 要解决的。**学它的展示形态，别学它的算法。**

---

### ❌ 导师式授课流程（完整版）

对方的 `interactive-tutor` 是通用教育平台级功能：读整份材料 → 划分知识点 → 出诊断题 → 排学习顺序 → 逐课讲解 → 出正式习题 → 批改 → 答疑 → 错题本 → 学习报告 → 双依赖图。这套东西**是给"读教材/备考课程"设计的，不是给"记单词"设计的**。

**但它有一个片段值得单独拿**：

> **每课结尾问难度**：A 过于简单 / B 适中 / C 过于困难（空白默认 B）+ 可选疑问。空白 = 没难度信号；非空 = 先答疑再调下一课。

这个机制在你的 `writing workspace`（评阅之后）和 `l3 grading`（评卷之后）**可以低成本复用** —— 判完分顺手问一句"这篇对你的水平是偏易/适中/偏难"，比什么都不问强。

**完整版不要做。** 它跟你 L3 的做题/评卷线是平行宇宙。

### ❌ 手写作文答题卡图片

`render-handwritten-essay-card` 把作文生成成"考场手写答题卡照片"（生图，提示词强调手写印刷体 + 负面提示词禁止电脑字体）。

**很新奇，但我认为不适合你。** 理由：它是个一次性 gimmick，做完没有第二次使用场景。而生图有成本、有不确定性、结果不可复现。你的 writing workspace 已经能生成结构化的范文和批改，比一张假手写照片有用得多。

## 半成品：可扩展但不必现在做

### 挖空的规则层

**你有的**：`buildClozeMcq`（`src/domain/l2-task.ts:171-210`）—— 词边界正则替换 lemma 为 `____`，4 选 1。已经处理了防答案泄露（`:181-183` 用 `replaceAll`，避免只替换首处）。

**对方有的**：`mark-memory-spans` —— 整段文本挖空，带**完整的质量规则层**：覆盖率上限 85%、单 span 不超 40%（有明确主干时可放宽到 50%）、挖空后剩余文字必须仍能分辨句子主干、专业术语不可从中间切开（`utils/references/术语表.txt`）、以及"答案在紧接的比较句里直接出现 = 泄露"这类具体判据。

**差距**：你的 cloze 是"挖目标词给选项"（选择题形态），对方是"挖句子让用户填"（产出形态）。**两者不冲突，是不同题型。**

**建议**：你缺的不是规则层，是**产出型 cloze 这个题型本身**。如果要加（比如背句子译文），把上面那几条质量规则抄过来即可 —— 尤其"挖空后主干仍可读"这一条，是产出型 cloze 能不能用的关键。

### 跨材料学习报告

**你有的**：`L3ErrorBookPage.tsx:99` 错题库是派生视图，已经合并题级 + 句级两条腿（`:135-138`）。但只覆盖 L3 做题/练习。

**缺的**：不跨 L2 复习 / L3 做题 / 写作 / 外部材料。

**建议**：**性价比很高的一个扩展** —— 派生视图的骨架你已经搭好了，只要把查询源从 `l3_question_attempts + l3_practice_attempts` 扩到 L2 的 `review_logs`，就能得到一份"这个月我在哪些地方反复栽跟头"的跨轨道报告。**但要控制边界**：这是派生视图，不要给它建表（你 CONTEXT.md 里对错题库已经立了这条规矩）。

## 建议的执行顺序

1. **复习日历** —— 数据已在库里，纯 UI 活，且能立刻兑现 FSRS 的价值
2. **CSV 词表导入** —— 你的 typewords-dict 数据等着用，stub 路径已通
3. **能力路由** —— 一次投入，长期降低 agent 和新用户的认知成本
4. **葫芦「缩时曲线」**（每轮耗时递减曲线） —— 纯统计与展示，不动 FSRS 计算，补的是 FSRS 完全缺失的"我在变强"信号
5. **攻坚包加 4+4 滚动 + 80% 门槛** —— 考前冲刺是葫芦的正确位置
6. **对话音频的"逐字稿"部分**（不做 TTS） —— 先验证改写质量，再决定是否投音频
7. 其余进 backlog，观察真实使用中是否出现需求

**最后一句**：对方项目的功能多是因为它是**给不同人不同阶段用的工具箱**。vocab-ob 的价值恰恰在于**窄而深**。抄功能之前先问一句：这个功能是在服务"记单词"这条主线，还是在把系统撑宽？上表里 P0 的两个、P1 的三个，都还在线内；backlog 那两个需要你实际用过一阵再判断。
