## 〇、决策记录（已定稿）

### D-A · 入池条件 = 先学后刷
定格源从 `wordbook_items`（真实库几乎为空，app 无写入口）改为该词书的**复习牌堆**中**至少评分过一次**的词：

- SQL 口径：`user_word_progress` 该词书内 `state IN ('learning','review','relearning')`；序 `created_at ASC, word_id ASC`（加入复习的顺序，贴近"从头到尾过一遍"）。
- 排除 `new`：没见过的词不逼"回忆"；排除 `suspended`：用户主动放下的，冲刺不替他捡回来。
- 连带自洽：`new` 不入池 ⇒ 挂起开关只作用于入池词（新词照常到期）；挂起快照/恢复机制**不变**（冻结集本身就是进度行）。

### D-B · 卡面精致化（翻开后按 L1 卡背三层信息披露）
- **Tier0**：`short_definition` 主行（大字）。
- **义项层（"词义按重要程度"的现成数据源）**：`core_definitions`（`words.core_definitions jsonb`，入库时已按 priority 排序、全库 100% 覆盖），直接喂现成组件 `SenseList`（纯展示、零拉取）；无 `core_definitions` 时走 `definition_md` markdown 降级（与 L1 卡背同一判据）。
- **助记锚（显著，非低调常驻）**：`mnemonic_text` + `mnemonic_type` 徽标。
- **例句**：`examples` 前 1–2 条（text + 可选来源/译文，防御性渲染）。
- **Tier2**：`semantic_chain`（默认折叠、可点展开）。
- **硬约束不变**：单卡路径零请求 ⇒ 上述全部字段必须随**页载荷**批量带下；**禁止** `useWordDetail`（每卡一请求）、**禁止**嵌 `ReviewCardView`；**允许**复用 `SenseList` 这类纯展示子组件。

### D-C · D1 修复
`settlePage` 的 "total 与本页存活词数不符" 给稳定业务码 `HULU_PAGE_ALIVE_MISMATCH`（HTTP 仍 422）；前端 settle 捕获该码 → **自动重取本页 + 轻提示**，不落错误页。

## 三、M3 D1 修复

- 服务端：`settlePage` 的 total/alive 不符错误带 `code: "HULU_PAGE_ALIVE_MISMATCH"`（422 语义不变；改错误映射把 code 透出到响应体）。

- 测试：jsdom（模拟该 422 → 断言重取且不跳错误页、无重复结算）；service 测试（code 稳定、该路径仍 422 不落库）。
