# 生词入本即记流水 —— 设计稿（R1 扩展）

- **日期**：2026-10-11
- **范围**：捕获窗「加入生词本」动作顺带在当日流水留一条条目；并为所有带词软引用的条目增加读时信号投影。
- **结论（TL;DR）**：可行。**路由层 best-effort 记流水**（不进捕获事务）+ **新增内置类型 `word`（生词）**（cap 10→11，`note` sort 幂等升）+ **`entrySeq` 进 capture 响应**（非 breaking）+ **信号案 A + 降级**（读时派生，不写回条目）+ **硬删除词 → 灰色「词已不在」**（alias 自动跟随）。两条线可并行：信号投影（纯读面）先行，入本即记流水（有写入）后做。

---

## 0. 背景与目标

捕获窗「加入生词本」= `POST /capture`（`CapturePage.tsx`，仅 `missing` 态出现）→ `CaptureService.capture()`：建/复用 stub 词 → 加进默认词书 → 有原句则同事务写 L3 三件套。**今天它不写任何流水。**

目标：让这次调用**顺带在当日流水留一条**，内容带上词形 + 可选原句/来源，词软引用 `meta.wordSlugs=[slug]`。配以上轮的信号投影，形成闭环：

- **账本行**（不可变）：哪天、哪个词、哪句原话 —— "这个词我是哪天收的"
- **信号徽标**（读时派生）：这个词现在什么状态 —— "待补释义 → 已补 → L2 已晋升"

顺带解决"词 → 条目"反查：入本即留痕后，账本行直接在那儿，不需要给 `meta.wordSlugs` 建 GIN 索引。

## 1. 既有机制（证据）

### 1.1 capture 路径不写流水


`capture()` 事务体（`:100-137`）只有三步：`wordbooks.addWords` → `noteEntries.listVisibleByWordIds` → L3 三件套。**无 `dailyCapture` 调用。**

### 1.2 条目 → 词的软引用已存在


### 1.3 appendEntry 自带 seq 重试（重开事务）

```97:132:src/services/daily-capture.service.ts

    //（Postgres 在 23505 后 abort 当前事务，同事务内重试必然失败）。
    for (let attempt = 0; ; attempt += 1) {

          const types = await repos.dailyCapture.listTypes(input.userId);

          if (!known) throw new BusinessRuleError(`unknown daily capture entry type "${entryType}"`);
          return repos.dailyCapture.insertEntry({ … });
        }, { actorId: input.userId });
```

**关键**：23505 后要**重开事务**（Postgres abort 后同事务内重试必然失败）。塞进 capture 的 tx 就绕过这个机制，且并发撞 seq 会把整个捕获拖回滚。

### 1.4 ensureDefaultTypes 是 ON CONFLICT DO NOTHING



## 2. 决断（六个点）

### ① entry_type：新增内置 `word`（生词）

| 选 | 做法 | 弃/取 |
|---|---|---|
| **(a) 新增 `word`** ✅ | 日文件分组 `## 生词 (n)`，专用 absorptionHint | **取**：分组最清晰；hint 可挂"不再 add_word/bind_l3" |
| (b) 复用 sentence/phrase | 有原句→`sentence`，无→`phrase` | **弃**：不成组；agent 会按既有 hint 提 `bind_l3`/`add_word`，虽有去重（§1.5）但浪费提案；无法挂专用 hint |
| (c) 一律 `note` | catch-all | **弃**：不可扫 |

### ② entrySeq 进响应：加（nullable，非 required）

`verify-openapi-breaking.ts:198-204` 只报"required response field 被删除"——**新增 optional property 不报**。`captureResponseSchema` 是 `.strict()`（`capture-response-contract.ts`）→ openapi `additionalProperties: false` + 全属性列名；加 `entrySeq` 到 properties、required 不变 → **非 breaking**。

### ③ 软隐/改名：硬删除 → 灰色「词已不在」；改名走 alias

`findBySlug(slug, { allowAlias: true })`（`capture.service.ts:85`）—— slug 绑到另一个词时信号自动跟随。硬删除是唯一需要特殊显示的场景。

### ④ 写在哪层：路由层编排 + best-effort

不进 capture 事务（§1.3）。路由层调 `services.dailyCapture.appendEntry`（独立事务，自带 seq 重试 + 类型校验 + seed），失败 best-effort 吞掉——与 L3 三件套同哲学（§1.1）。

### ⑤ 信号方案：案 A + 降级（≥3 词或窄屏退 B）

入本条目固定 1 词，案 A 行内只多 1 枚徽标，不触发降级。降级只保护手动记的多词条目。

### ⑥ 读面覆盖：日视图 + 证据包；日文件 markdown 不标

日文件是确定性静态投影（`GET /days/:date/file`，`daily-capture.ts:10-11`）——把动态信号烙进去必然过期。

## 3. 数据模型变更

### 3.1 新增内置类型 `word`

`src/domain/daily-capture.ts` 的 `DEFAULT_DAILY_CAPTURE_TYPES` 加第 7 项：

| type_key | label | absorptionHint | sort |
|---|---|---|---|
| `word` | 生词 | 出生即入本（捕获窗触发）；L3 三件套已在捕获时写入；吸收时不再提 `add_word` / `bind_l3`，可提 `enqueue_review`（补复习卡）或 `file_method`（留档） | 5 |

### 3.2 cap 10→11 + note sort 自愈

`DAILY_CAPTURE_VISIBLE_TYPE_CAP` 注释口径从「6 内置 + 4 自定义席位」→「7 内置 + 4 自定义」——**自定义席位数不变**，只是数字表达变了。

`ensureDefaultTypes` 是 `ON CONFLICT DO NOTHING`（§1.4），已有用户行不更新 → INSERT 前加一条幂等 UPDATE：

```sql
UPDATE daily_capture_types SET sort = 6
WHERE user_id = $1 AND type_key = 'note' AND sort = 5
```

只命中内置 `note`（sort=5 是 seed 值）；用户改过 sort（≠5）的不碰。然后 INSERT `word`(sort=5) `DO NOTHING`。`listTypes` 的 `ORDER BY sort ASC, type_key ASC`（`daily-capture.repository.ts:62`）保证 `word`(5) 在 `idea`(4) 之后、`note`(6) 之前。

### 3.3 无 schema 迁移

`daily_capture_types` / `daily_capture_entries` 表结构不变。类型 seed 是数据级（`ensureDefaultTypes` 幂等），不走 drizzle 迁移。

## 4. 接口变更

### 4.1 capture 响应 +entrySeq

```ts
// src/http/capture-response-contract.ts
export const captureResponseSchema = z.object({
  word: z.object({ id: z.string().uuid(), title: z.string() }),
  existed: z.boolean(),
  l3Status: z.enum(["captured", "deferred"]),
  entrySeq: z.number().int().min(1).nullable().optional(),  // ← 新增
}).strict();
```

路由层注入（不改 `CaptureService`）：

```ts
// src/http/routes/capture.ts（:30-44 扩展）
const result = await services.capture.capture({ … });
let entrySeq: number | null = null;
try {
  const entry = await services.dailyCapture.appendEntry({
    userId,
    entryType: "word",
    content: parsed.data.sentence?.trim() || parsed.data.headword,
    meta: {
      wordSlugs: [result.word.slug ?? slugifyHeadword(parsed.data.headword)],
      ...(parsed.data.sourceUrl ? { sourceUrl: parsed.data.sourceUrl } : {}),
      ...(parsed.data.obsidianRef ? { obsidianRef: parsed.data.obsidianRef } : {}),
    },
  });
  entrySeq = entry.seq;
} catch { /* best-effort：与 L3 三件套同哲学 */ }
return c.json(captureResponseSchema.parse({ ...result, entrySeq }), 201);
```

`CaptureResult` 接口不动——`entrySeq` 在路由层组装时注入。`result.word.slug` 若不存在于 CaptureResult，用 `slugifyHeadword(headword)`（capture.service 已校验 slug 非空，`:78-81`）。

### 4.2 daily-capture 日视图 +wordSignals

```ts
// GET /api/daily-capture/days/:date 响应（dailyCaptureDayResponseSchema）
{
  observedAt: "2026-10-11T05:12:00.000Z",   // ← 新增：投影时刻
  entries: [{
    …,
    wordSignals: [                           // ← 新增：按 meta.wordSlugs 读时派生
      { slug: "ecase", state: "stub"|"ready"|"gone",
```

`state` 派生规则：`words.slug IN (meta.wordSlugs)` 批量查；命中且 `definition_md <> ''` → `ready`；命中且空 → `stub`；未命中 → `gone`（硬删除或 slug 变更后无 alias 指向）。

### 4.3 证据包 +signal

`GET /days/:date/export` 已有 `entry.words` 词快照（`daily-capture.ts:162-163`："关联词语境计数"），加同一个 `signal` 字段。agent 据此判断"该词 L3 已存在，不再提 `bind_l3`"。

```ts
// 读时派生，不写库。一天几十个 slug，走 words.slug 唯一索引批量 IN。
async function wordsBySlug(slugs: string[]): Promise<Map<string, WordSignal>> {
  if (!slugs.length) return new Map();
  const rows = await repos.words.findBySlugs(slugs); // SELECT … WHERE slug = ANY($1)
  return new Map(rows.map(r => [r.slug, {
    slug: r.slug, state: r.definition_md ? "ready" : "stub",
    hasDefinition: !!r.definition_md, l2Promoted: r.l2_promoted, updatedAt: r.updated_at,
  }]));
  // meta.wordSlugs 中未命中的 slug → state="gone"（渲染器侧补）
}
```

## 6. 边界与连带

### 6.1 吸收语义规则

`word` 类型的 `absorptionHint` 明确："出生即入本；L3 已在捕获时写入；吸收时不再提 `add_word` / `bind_l3`，可提 `enqueue_review` 或 `file_method`"。agent 提案规范天然遵守，不需要在 absorption 服务层加强制拦截（去重兜底已在，§1.5）。

### 6.2 软隐/改名

- **改名 = alias**：`findBySlug(slug, { allowAlias: true })` 命中 alias 指向的词 → 产出正常 signal，无需特殊处理。
- **硬删除**：`wordsBySlug` 查不到 → `state="gone"` → 灰色「词已不在」徽标。`title="该词已从词库删除；流水文本不可变，此为读时投影"`。
- **流水文本不可变**：不隐藏 `⤳ [[slug]]` 链接（那是篡改账本）。

### 6.3 重复与出生状态

- 同日同词多次入本 → 记多条（动作流水）。UI 只在 `missing` 态给按钮，天然少见。不做 `(user, slug, date)` 去重。
- 出生状态 `raw`（进"未回顾"计数，接上回顾/置要/归档流程）。

### 6.4 日文件 markdown 不标信号

`GET /days/:date/file` 是确定性静态投影（`daily-capture.ts:10`）。信号是动态投影，每次读取最新。把动态烙进静态必然过期。日文件保持纯静态，信号只在交互读面（日视图 / 证据包）出现。

### 6.5 复制当日文件的副作用

入本条目会让「复制当日文件」多出 `## 生词 (n)` 分组下的行 → 改 Obsidian 同步文本。这是新行为的必然副作用，与 §6.4 的"日文件不标信号"是两件事（一个是多了行，一个是行内不加徽标）。

## 9. 未决/风险

- **cap 10→11 是 M2 定稿 §14 口径的数字修订**（实质不变：4 自定义席位保留）。若后续需要正式 ADR 留痕，可补 `docs/adr/0043-*.md`（cap 口径修订）。当前先在本文档 + 代码注释记录。
- **`result.word.slug` 是否在 CaptureResult 中暴露**：若 CaptureResult 只返回 `{id, title}` 不含 slug，路由层须用 `slugifyHeadword(parsed.data.headword)` 自算 slug（capture.service 已校验非空）。实现时确认 CaptureResult 形状。
- **多设备并发同日入本**：seq 撞 23505 由 appendEntry 重试兜底（§1.3），不波及捕获主事务。
