## 〇、可行性结论（审查通过，附 8 处修正）

设计稿的架构判断经源码逐条核实，全部成立：

- 只新增两张表、一组新端点、一个显式模式项；**不改任何已有表**；回退 = 删两张表。
- 不进 `sessions` 表（枚举、唯一索引、zen 映射三条理由），不进 `l3_sessions`（它的世界是语境不是词）。
- 新表无 FSRS 列，服务层不引用 `review.service`，缩时曲线只读 `hulu_rounds` —— 零 FSRS 写入是**结构性**的。
- OpenAPI breaking 门禁只遍历基线 paths，纯新增端点**不会**触发（`scripts/verify-openapi-breaking.ts:315-377`）。

唯一碰到既有数据的地方是**可选、默认关闭**的挂起，它不走一键遗忘的批次恢复。

但复验发现 8 处旧稿口径与现状不符（其中 1 处会写坏 FSRS 可见状态），必须先修正再实现。§二 的 R1–R8 就是这 8 处修正，**实现时以修正后的口径为准，不得沿用旧稿原文**。

## 一、定位与五条不变量

葫芦是挂在 **L1 词书**上的**阶段性冲刺计划**：整批词按页推进、页级检索闸门（默认 80%）、多轮滚动、只记轮次耗时、零 FSRS 写入。它不替换 `review / cram / preview / zen / ladder` 任何一个，是第 6 个**显式**复习模式。

1. **显式模式**：`reviewModes` 数组加一行 `{ key: "hulu", ... }`，不选则代码路径分支不可达（ADR-0036 §4 修订的先例）。
2. **不进 `sessions` 表**：枚举只认 `review/cram/preview/l2_drill`（`schema.ts:344`）；`idx_sessions_one_active` 的坐次语义与「跨周计划」粒度错位。
3. **不进 `l3_sessions`**：其类型枚举与抽样对象是 `context_id`，不是词。
4. **零 FSRS 写入（默认）**：不写 `review_logs`、不写 `user_word_progress`、不调 `submitAnswer`；唯一例外是显式 `suspend_review` 开关（§六），它在构造上隔离。
5. **缩时曲线只消费 `hulu_rounds`**，不推广到 `review`（`due7d = dueToday * 1.5` 是前车之鉴，`stats.service.ts:63-68`）。

## 二、对旧稿的八处修正（R1–R8）

### R1【最重】挂起恢复：快照回写，不是统一恢复成 `review`

- 旧稿（深度设计稿 §五）：「只把清单里的行恢复到 `review`」。
- 问题：`state` 枚举是 `new / learning / review / relearning / suspended`（`schema.ts:278`）。把 `new`/`learning`/`relearning` 的行统一恢复成 `review`，等于让无 FSRS 记忆的行伪装成 review 态 —— 改变 `review` 队列行为，直接违反「另外五个模式一个字节都不差」。
- 先例：一键遗忘存挂起前 state 快照、原样回写（`forgetting.service.ts:9`、`review.repository.ts:744`），且批量挂起排除 `new`（`review.repository.ts:695`）。
- **定稿**：`suspend_snapshot jsonb` 存 `{ "<wordId>": "<挂起前 state>", ... }`，只记录实际被挂起的行；恢复时逐行回写快照 state，且仅当该行当前仍为 `suspended`。详见 §六。

### R2 `state` 写入落点：新增 `ReviewRepository` 方法（经审查批准的第 9 个写点），service 不得裸写 SQL

- 旧稿（深度设计稿 §8.2）：「若 `state` 写入收口到唯一仓库方法就调用它；散落各处就停下来」。
- 现状：`user_word_progress.state` 的写点有 **8 处**，全部在 `ReviewRepository` 一个类内但绝非单一方法：`insertNewCard`(:298)、`saveAnswer`(:434)、`suspendCard`(:576)、`bulkSuspendByWordbook`(:700)、`restoreBulkForget`(:744)、`markStaleForRecheck`(:878)、`markL1StaleForRecheck`(:904)、DB 侧 RPC `undo_review_log`(:789)。
- **定稿**：挂起/恢复实现为 `ReviewRepository` 的两个新方法（照 `bulkSuspendByWordbook`/`restoreBulkForget` 的形状，`requireTx` + actor 事务），这是该类第 9/10 个 state 写点，**经本文批准**。`HuluPlanService` 只调用方法名，不裸写 SQL，不新增第二个写 state 的 repository。

### R3 会话恢复：localStorage + 24h + 独立前缀，不是 sessionStorage + 30min

- 旧稿：「TTL 沿用 ADR-0036 §6 的 30 分钟」。
- 现状：ADR 文本已过时，实际机制是 **localStorage + 24h TTL**：经典复习 `vocab:review:session:`（`useReview.ts:112-113`），阶梯 `vocab:review:ladder:review`（`LadderReviewSession.tsx:43-47`，独立前缀先例）。
- **定稿**：葫芦用 `vocab:hulu:sprint:<planId>`，TTL = 24h，读时校验 `planId`/`roundNo` 与服务端一致，不一致即弃。超时丢失的代价 = 重走当前未结算页（未结算页本来就没入库）。

### R4 批量取词：新增只读端点，不复用 preview queue

- 旧稿：「只读卡面字段走现有词条读取接口」。
- 现状：唯一的批量出口 `GET /review/queue?mode=preview&wordIds=` 会先 `getOrCreateTodaySession`（`review.service.ts:203-208` → `session.repository.ts:30-52`）**INSERT 一行 `sessions`**，且词书锚定**默认词书**（`routes/review.ts:49`）；`/api/words` 列表 `limit ≤ 100`、无 direction 过滤（`schemas/http/index.ts:48-55`）。
- **定稿**：新增 `GET /api/hulu/plans/:id/pages/:no`，一次返回本页词卡渲染载荷，只读、无副作用（§七）。

### R5 耗时口径：墙钟，中断不切开

- 旧稿（实现计划 §5.3）：「中断退出再进入累计，由各段 `ended_at - started_at` 求和」。
- 问题：没有段表，与 R3 的 24h 恢复也配不上。
- **定稿**：一轮耗时 = 墙钟 `ended_at - started_at`，中断不切开。跨夜/跨天的长中断会虚高 —— 这是已知且接受的口径代价，曲线免责声明（§九）覆盖它，不为它建段表。`elapsed_seconds` 服务端夹取到 `[0, 86400×7]`（单轮上限 7 天，常量见 §四）。

### R6 direction：仅标签，不参与取词

- 旧稿（实现计划 §4.2）：「按词书（+可选 direction）取词」。
- 现状：`words` / `wordbooks` 都**没有** direction 列（方向只存在于 `word_l2_content`/`l3_sources`/工单/试卷，`schema.ts:879,902,1218,1329,1344`）。
- **定稿**：词集定格 = **整本词书**；`hulu_plans.direction` 只是可空标签（三值枚举同 ADR-0017），不过滤词集。创建 UI 不得提供「按 direction 选词」。

### R7 页结算幂等机制（旧稿未写，测试 6 依赖它）

- **定稿**：`hulu_rounds.pages_passed` 即页游标。页结算 = 单条条件 UPDATE：

  `UPDATE hulu_rounds SET pages_passed = pages_passed + 1, words_passed = words_passed + $passed WHERE id = $roundId AND user_id = $userId AND ended_at IS NULL AND pages_passed = $pageIndex`

  - `rowcount = 1` → 结算成功；
  - `rowcount = 0` 且该轮 `pages_passed > $pageIndex` → 重复提交，幂等返回现状；
  - `rowcount = 0` 且 `pages_passed < $pageIndex` → 跳页，`409`。

  原子、并发安全，不需要页级明细表。

### R8 原型断言计数不再引用

两稿分别写「33 项」「40 项」DOM 桩断言，数字不一致且断言脚本不在仓库内。交互语义以本文 §三 为准；不再引用任何断言计数。

## 三、目标行为

```
创建（整本词书定格词集、服务端风险校验、可选挂起开关）
  → 第 n 轮开始（记录 started_at；已有未收尾轮则续用）
      → 逐页：遮答 → 尝试回忆 → 翻开 → 自认过/不过 → 页结算
            通过率 < gate → 整页自认清零，退回学习态，不入库，不发请求
            通过率 ≥ gate → POST 页结算（计数+游标），进下一页
      → 允许回看已结算页（只读），不允许改结果
      → 已删词的定格位置只缩不换；整页存活词数为 0 的页服务端自动通过
  → 第 n 轮收尾（写 ended_at / elapsed_seconds，墙钟夹取）
  → 未到目标轮数：不生成任何复习，直接进下一轮
  → 到目标轮数：计划 completed（同事务恢复挂起，若开过开关）
  → 任何时刻可放弃：abandoned，已有轮次保留（同事务恢复挂起）
```

创建时风险三级（服务端重算，不信任前端）：

| 条件 | 结果 |
| --- | --- |
| 未填考试日期，或日期已过 | 422 拒绝 |
| `target_rounds × ceil(词数 / 400)` > 剩余天数 × 2 | 422 拒绝，响应携带 `{ need, left, perRound }` |
| 只是 > 剩余天数 | 放行，响应携带 `risk.level = "warn"`，计划页持续显示缺口 |
| 其余 | 放行 |

`400 词/天` 是初始常量，唯一来源是 `src/domain/hulu-sprint.ts` 的 `HULU_WORDS_PER_DAY`，不是测量值、不是承诺。

闸门：`passed / total ≥ gate_ratio` 放行（用计划行的列值，不写死 0.8）；`total` = 本页**存活**词数。闸门判定是纯函数 `huluGateDecision(passed, total, gateRatio)`（`src/domain/hulu-sprint.ts`），前后端共用同一口径；服务端在页结算时复验一次，不过闸的提交拒绝（422）。

| 列 | 类型 / 约束 | 说明 |
| --- | --- | --- |
| `id` | uuid pk default gen_random_uuid() | |
| `user_id` | uuid not null，FK → `profiles(id)` cascade | |

- `CONSTRAINT hulu_plans_id_user_unique UNIQUE (id, user_id)` —— 供 `hulu_rounds` 复合 FK 用（照 `sessions_id_user_wordbook_unique`，`schema.ts:342`）。
- 部分唯一索引 `idx_hulu_plans_one_active ON (user_id, wordbook_id) WHERE status = 'active'`。
- 普通索引 `(user_id)`。
- `ENABLE ROW LEVEL SECURITY` + policy `hulu_plans_own_all`：`auth.uid() = user_id`（using + with check）。
- `GRANT SELECT, INSERT, UPDATE, DELETE ON TABLE "hulu_plans" TO "vocab_app";`

### 4.2 `hulu_rounds`

| 列 | 类型 / 约束 |
| --- | --- |
| `id` | uuid pk default gen_random_uuid() |
| `plan_id` | uuid not null，FK → `hulu_plans(id)` cascade |
| `user_id` | uuid not null，FK → `profiles(id)` cascade；复合 FK `(plan_id, user_id)` → `hulu_plans(id, user_id)` |
| `round_no` | smallint not null；`UNIQUE (plan_id, round_no)` |
| `started_at` | timestamptz not null |
| `ended_at` | timestamptz null（空 = 进行中，全计划至多一个） |
| `elapsed_seconds` | integer null，收尾写入后不改 |

| `words_total` | integer not null（冗余 cardinality(word_ids)） |

索引：`(plan_id)`。RLS + `hulu_rounds_own_all` 同上。GRANT 同上。

「全计划至多一个未收尾轮」由服务层在事务内保证（`SELECT ... FOR UPDATE` 计划行后判断），不另建部分唯一索引。

### 4.3 刻意没有的

页级明细表、词级通过记录、`plan jsonb`、`version` 列。失败页不留记录；「没通过」是页级比例事件，不接错题库（错题库 = `attempts(outcome='wrong')` 派生视图，ADR-0019 §1）。

### 4.4 回退

`DROP TABLE hulu_rounds, hulu_plans;` 无数据搬迁。

## 六、挂起最小实现（可选，默认关）

**目的**：冲刺期让本批词退出 `review` 到期队列（队列 SQL 已过滤 `state != 'suspended'`，`review.repository.ts:116/147/182`），计划结束自动回来。**不做**「检测到冲刺就自动暂停」——静默接管是 ADR-0036 §4 否决过的。

**开关只能创建时设定**，不支持中途切换（要换就放弃重建；省掉一台状态机）。开启前前端必须明示：「这批词会暂时退出到期队列，计划结束或放弃时自动回来」。

**挂起范围**：`word_ids` 中 `state <> 'suspended'` 的行（含 `new` —— 有快照即安全，且目标是整批退出到期队列；与一键遗忘排除 `new` 的语义不同，动机不同）。

**实现**（R1/R2 的落点，`ReviewRepository` 两个新方法，均 `requireTx`，在 actor 事务内执行）：

1. `bulkSuspendByWordIds({ userId, wordbookId, wordIds })`：单条语句完成快照+挂起并回返快照——
   `UPDATE user_word_progress u SET state = 'suspended', updated_at = now() FROM (SELECT id, word_id, state AS old_state FROM user_word_progress WHERE user_id = $1 AND wordbook_id = $2 AND word_id = ANY($3::uuid[]) AND state <> 'suspended') s WHERE u.id = s.id RETURNING s.word_id, s.old_state`
   结果写入计划的 `suspend_snapshot`。**不写 `review_logs`**。
2. `restoreSuspendSnapshot({ userId, wordbookId, snapshot })`：`jsonb_to_recordset` 展开快照，逐行 `SET state = s.old_state`，`WHERE u.state = 'suspended' AND u.word_id = s.word_id`（只回写仍处挂起的行）。恢复后同事务清 `suspend_snapshot = NULL`。

**时机**：apply 在创建计划的**同一事务**；restore 在计划转 `completed`/`abandoned` 的**同一事务**。

**交错安全**（与一键遗忘、手动挂起互不伤）：

- 先遗忘后葫芦：遗忘批次不含葫芦将挂起的词（当时未挂起）→ 葫芦快照照常；两条恢复路径各自按各自清单回写。
- 先葫芦后遗忘：遗忘 apply 只挂 `state NOT IN ('suspended','new')` 的行，葫芦已挂起的词被跳过 → 不进遗忘批次 → 遗忘 restore 不碰它。
- 计划期间用户手动挂起：被葫芦挂起的词不在到期队列，用户无从再挂；用户在队列里手动挂起的词不在葫芦快照内 → 葫芦恢复不动它（对应测试 7）。
- 内容变更 `markL1StaleForRecheck` 的 `state = CASE ... ELSE state` 保留 `suspended`，不冲突。

**已知且接受**：stale active 计划（考完不完成也不放弃）会让词一直挂起。本期不做自动过期；P2 在计划页对 `exam_date` 已过的计划显示提示横幅，提醒用户放弃。

## 七、接口契约（全部新增，前缀 `/api/hulu`）

登记到 `src/http/operations.ts`，模式照 l3-sessions / forgetting（读 = `owner`/`agent`/`none`，写 = `owner`/`owner`/`sessionMutation`）。响应 schema 放 `src/http/hulu-response-contract.ts`，全部 `.strict()` 且类型对齐 service 导出类型。

| 方法 | 路径 | operationId | 作用与幂等语义 |
| --- | --- | --- | --- |
| POST | `/api/hulu/plans` | `createHuluPlan` | 创建（含定格+风险校验）。同词书已有 active 计划 → 200 返回它，不报冲突 |
| GET | `/api/hulu/plans/:id` | `getHuluPlan` | 计划 + 轮次列表（曲线数据源） |
| GET | `/api/hulu/plans/:id/pages/:no` | `getHuluPlanPage` | 本页词卡渲染载荷（R4），只读 |
| POST | `/api/hulu/plans/:id/rounds` | `startHuluRound` | 开始下一轮；已有未收尾轮 → 返回它；已到目标轮数 → 409 |
| POST | `/api/hulu/plans/:id/rounds/:no/pages` | `settleHuluPage` | 页结算（R7 游标幂等）；不过闸 → 422；跳页 → 409 |
| POST | `/api/hulu/plans/:id/rounds/:no/finish` | `finishHuluRound` | 收尾；已收尾 → 返回它；末轮同事务完成计划 |
| POST | `/api/hulu/plans/:id/abandon` | `abandonHuluPlan` | 放弃；已 abandoned → 返回它；已 completed → 409 |

请求 schema（`src/schemas/http/index.ts`）：

- `huluPlanCreateSchema`：`{ wordbookId: uuid, direction?: "通用"|"考研"|"雅思"|null, examDate: date 字符串, targetRounds?: int 2..8 = 4, pageSize?: int 5..50 = 20, gateRatio?: number 0.50..1.00 = 0.8, suspendReview?: boolean = false }`
- `huluPageSettleSchema`：`{ pageIndex: int ≥ 0, passed: int ≥ 0, total: int ≥ 0 }`
- `huluRoundStartSchema`：`{ startedAt?: ISO datetime }`（缺省服务端 now()；越界夹取）
- `huluRoundFinishSchema`：`{ endedAt?: ISO datetime }`（同上）

## 九、缩时曲线（P2）
