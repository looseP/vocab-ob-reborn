## 1. 候选 A：真实复习日历（推荐首发）

### 事实
- `GET /review/stats/dashboard` 已存在，但 **forecast 是假的**：`due7d = dueToday*1.5`、`due14d = dueToday*2`（`src/services/stats.service.ts:63-68`，注释自认没读 `due_at`）。
- 过去侧已有 UI 与端点：`MasteryHeatmap.tsx` + `GET /review/heatmap`（按日复习量）。
- 未来侧的真实数据源齐备：`user_word_progress.due_at`；索引 `idx_user_word_progress_due`、`idx_uwp_wordbook_due` 已在（聚合便宜）。

### 设计决策点（含推荐）
1. **假 forecast 换真** —— `computeForecast` 改为真查 `due_at` 分桶（now → +7d → +14d → +30d）。判据：每个数字可回溯到 SQL 桶。**推荐做**（顺手清掉 V10 类假指标，这是仓库有前车之鉴的地方）。
2. **日历视图** —— 过去 N 天 = 复习量（`review_logs`）；未来 N 天 = 到期量（`due_at`）；今天两值都给（已复习 x / 待做 y）。
3. **当日详情** —— 新薄端点 `GET /review/day?date=YYYY-MM-DD&scope=due|reviewed&limit=`（新文件 + 棘轮 bootstrap 条目；只读、零写入）。
4. **不掺和 hulu** —— 日历只读 FSRS 面；计划进度/剩余轮数留在计划页，**避免第二个"计划视图"**。
5. **展示口径** —— Asia/Shanghai 日历日（仓库既有口径）。

### 红线与验收
- 只读、不改调度；预测数字与 SQL 直查一致（真库对账）；"今天 due 数"与复习页首屏一致。

## 2. 候选 B：合规两项（数据已在库，口径本轮钉死）

### 事实（本轮实测，取代 10-04 文档的模糊说法）
- `examples[].source_type` 是**示例级字段**（jsonb，无 DB 约束）。全库分布：
  `press 6407 / reference 302 / institution 38 / academic 16 / quote 3 / media 1`。
- **238 条「构造参考」示例全部被标成 `reference`** —— 自撰语料没有机器可读标记。
- 其 `source` 文案形如：`构造参考 · Buddhist（迁移包 SD 取材，待网页核验）` ——
  **把「取材方式」与「核验状态」两种事实挤进了一个人类可读字符串**。
- 「待网页核验」= **216 条**，它不是类型问题，是**核验状态被写进了文案尾巴**。

### 设计决策点（含推荐）
1. `examples[].source_type` **新增取值 `constructed`**，回填 238 条（口径：`source ~ '构造参考'`）。
   ⚠️ 枚举的代码归属先定位（examples 是无约束 jsonb，枚举在导入器/类型里，不在 DB）。
2. 「待网页核验」216 条：**清洗 `source` 文案**；若要保留状态，做成**独立字段**
   （如 `verified.pending_web_check`），不要再进文案 —— 否则 UI/导出都读不可靠。
3. **上游同步**：语料导入/迁移包脚本同口径改（否则下次导入回潮）。

### 红线
- 不做"不存在的需求"（回填必须对应真实语义）；只增字段/清洗文案，不改既有键语义。

## 4. 候选 D：变强信号（需先决定"补采集"）

### 事实（我实测）
- `review_logs.metadata.duration_ms` **目前只有阶梯路径在写**（`LadderReviewSession` 发送 `durationMs`）；
  **经典 L1 复习（`useReview`）不发送该字段 → 经典复习没有耗时数据**。
- 今天就有数据的真实量：rating 序列、`stability`、`scheduled_days`、`lapse_count`、`review_count`。

### 设计决策点（含推荐）
1. **两条路**：A) 先用现成量做"变强"（平均 stability 走势 / again 率 / 平均间隔增长）；
   B) 先补采集（经典提交加**可选** `durationMs`，照 ADR-0036 §3「可选新增＝非 breaking」先例），耗时趋势从当日起积累。
2. **推荐 A 先行**（当天就有数据），B 作为一天的小改动另排。
3. 红线：只读 `review_logs`/`user_word_progress`；**与 hulu 曲线不共图**；每个点可回溯到行（不发明指标）。
