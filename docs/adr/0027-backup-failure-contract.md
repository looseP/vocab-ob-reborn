# ADR-0027: 备份失败契约（失败不删本地 + 保留按"已异地校验"推进）

- **Status**: Accepted
- **Date**: 2026-09-12
- **References**: ADR-0022（单 owner 自托管）、`scripts/postgres-backup.ts`、`docs/operations/postgresql-backup-recovery.md`
- **上游**: 2026-09-12 后端完备性拷问会话（第二轮 Q7 裁决）

## Context

备份链路本身已经很硬：自定义格式 `pg_dump` + 原子 rename（`scripts/postgres-backup.ts:295`）+ sidecar manifest 含 sha256/迁移数/表数/函数数（`:297-307`）+ 可选 HMAC 签名（`:309-312`）+ object-lock 只读（`:318-320`），并由容器内调度器按 `BACKUP_INTERVAL_MS` 运行。

但**两件事从未定义**：

1. **异地**只是运行手册的建议（"每周手工复制到加密外接盘/可信云盘"），没有强制，也没有证据；
2. **失败语义**空白——尤其"retention 清理"与"上传失败"相遇时：若清理按份数无条件推进，**远端上不去的那天恰好可能删掉本地最后一份好备份**（备份系统最经典的失效模式）。

## Decision

1. **上传失败 = 本地副本保留 + 任务状态失败 + 告警**。**绝不因上传失败而删除、覆盖或重做本地副本**（失败只允许"少了一份异地副本"，不允许"少了一份备份"）。
2. **retention 清理只按"已成功且已异地校验"的份数推进**；本地份数触顶时，优先保留**最近一份成功份**无论其异地状态。
3. **凭据最小权限**：上传凭据仅允许写 `backup/` 前缀（泄露后果可控）；远端保留 object-lock。
4. **远端校验不只比 sha256**：每月一次"**远端下载 → 隔离库恢复**"演练——远端静默损坏是异地备份的第二大失效模式，只比哈希发现不了"下载得下来但恢复不了"。
5. **文档记录 `RPO ≤ 24h` 与实测 `RTO`**（把承诺变成数字，而不是形容词）。

## Tradeoffs

- **失败即失败 vs 失败重试直到成功**：立即失败 + 保留本地，换来状态诚实与最坏情况下的可用性；代价是"异地副本短暂落后"需要人工介入（告警负责叫醒）。
- **按已校验份数清理 vs 按本地份数清理**：前者让清理依赖远端状态（多一点耦合：本地 manifest 必须记录"远端已校验"标记）；换取不会自毁。
- **月度远端恢复演练 vs 只比哈希**：演练成本是每月一次的手工动作；换取能发现"哈希对但恢复不出来"的损坏。

## Consequences

- ✅ 备份的失败模型明确：最坏情况是"少一份异地副本"，而不是"没有备份"。
- ✅ 异地从"建议"升级为"有证据的流程"（凭据权限 + 校验 + 演练 + RPO/RTO 数字）。
- ⚠️ 本地 manifest 需要新增"远端已校验"状态位，备份任务与远端状态耦合（实现时要注意"状态写入"与"文件落地"的原子性）。
- ⚠️ 上传失败必须**响亮**（任务状态 + 告警），否则会退化成"以为有异地备份，其实没有"——这是比"没有备份"更危险的认知状态。
